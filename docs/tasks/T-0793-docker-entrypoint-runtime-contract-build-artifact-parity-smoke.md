# T-0793 — deploy step① docker-entrypoint.sh 런타임 계약 ↔ 실 build/runtime artifact parity drift-detection non-gated build-time smoke 신설

## Why

PLAN.md §109(🟢 실 평가 e2e, P5) 및 deployment.md 의 배포 step① 은 `deploy/docker-entrypoint.sh` 가 컨테이너 entrypoint 로서 **DB migration 적용(`prisma migrate deploy`) 후 NestJS 앱(`node dist/src/main`)을 기동**한다. 이 entrypoint shell 이 하드코딩한 두 런타임 계약은 **실 build/runtime artifact 와 정합해야만 컨테이너가 crash-loop 없이 부팅되는 운영 contract** 다:

1. **`./node_modules/.bin/prisma migrate deploy`**(14행) — prisma CLI 바이너리가 `pnpm prune --prod` 후에도 `node_modules/.bin/` 에 존재해야 하고(즉 prisma 가 `devDependencies` 가 아니라 `dependencies` 여야 함 — 그래야 prod prune 을 생존), `migrate deploy` 가 배포 migration 정책(deployment.md "Migration 정책": idempotent·미적용 migration 순차 적용)이어야 한다.
2. **`exec node dist/src/main`**(20행) — 빌드 산출물 경로 `dist/src/main(.js)` 가 `nest build`(tsc)의 emit 위치와 정합해야 한다. 이 경로는 `tsconfig.json` 의 `outDir: "./dist"` + nest build 의 rootDir 추론(repo-root 의 `prisma.config.ts`/`scripts/` 가 루트로 추론을 끌어 `src/main.ts` 가 `dist/main.js` 가 아니라 `dist/src/main.js` 로 emit — docker-entrypoint.sh 주석 16~18행 명시)이라는 emergent 계약이다.

만약 누군가 silent 하게 (a) prisma 를 `devDependencies` 로 옮기거나(prune --prod 후 바이너리 소멸 → migrate deploy 단계에서 crash-loop), (b) `tsconfig outDir` 를 바꾸거나(`dist/src/main` 경로 무효 → 부팅 실패), (c) entrypoint 의 `migrate deploy` 를 다른 서브커맨드로 바꾸거나, (d) Dockerfile 의 `ENTRYPOINT`/`COPY dist·prisma.config.ts` 를 빼면 — 배포 컨테이너가 런타임에 silent crash-loop 한다. 이는 무인 배포 자율성(REQ-061 smoke-in-CI, REQ-062 배포 산출물 정합)을 깨뜨린다.

직전 sweep 들은 `deploy/daily-test.sh` 의 build-time seam 3종을 차례로 닫았다 — `step_eval` jest argv full-vector parity(T-0790), 머신 요약 JSON 스키마 contract(T-0791), HTTP step 계약 ↔ NestJS controller route decorator parity(T-0792). **T-0792 Follow-up (b) 는 다음 잔여 distinct build-time seam 후보 "`deploy/redeploy.sh`/`docker-entrypoint.sh`/`seed-llm-config.sh` 의 shell↔contract parity(genuine seam 인지·실 contract 가 존재하는지 HIGH bar 엄격 재판정 필요)" 를 명시**했다. 본 task 는 그 중 `docker-entrypoint.sh` 를 HIGH-bar 로 엄격 재판정해 채택한다 — genuine distinct seam 임을 사전 조사로 확인했다(make-work·rephrase 아님).

본 task 의 사전 조사(origin/main aebc5a58) 결과 — (1) **docker-entrypoint.sh 의 런타임 계약이 두드리는 실 artifact 가 전부 실존·안정** 하고, (2) **그 계약을 실 build/runtime artifact 와 대조하는 build-time smoke 는 0 부재** 다:

- **genuine 계약/artifact 실존 확인** (HIGH bar 통과의 핵심 — make-work 가 아님):
  - `docker-entrypoint.sh` 14행 `./node_modules/.bin/prisma migrate deploy` ↔ `package.json` 의 `dependencies.prisma`(실측: `dependencies` 에 `prisma`·`@prisma/client` 둘 다 존재, `devDependencies.prisma` 없음 → `pnpm prune --prod`(Dockerfile 41행) 생존). `migrate deploy` 는 ci.yml:175 `pnpm prisma migrate deploy` 와 동일 배포 정책.
  - `docker-entrypoint.sh` 20행 `exec node dist/src/main` ↔ `tsconfig.json` 의 `outDir: "./dist"`(12행) — `dist/src/main` 의 `dist` prefix 가 outDir basename 과 정합. `build` 스크립트는 `nest build`(package.json 12행).
  - `Dockerfile` 73행 `ENTRYPOINT ["./deploy/docker-entrypoint.sh"]` ↔ 본 shell 파일 자체(존재·동일 경로). Dockerfile 59행 `COPY ... /app/dist ./dist` + 63행 `COPY ... /app/prisma.config.ts ./prisma.config.ts` 가 entrypoint 의 두 경로(`dist/src/main`·prisma.config.ts 로더)를 valid 하게 만드는 실 artifact.
- **build-time cross-artifact smoke 0 부재** — `test/` grep 결과 `docker-entrypoint`/`dist/src/main`/`node_modules/.bin/prisma` 를 정적 대조하는 spec 0. CI 런타임 smoke(ci.yml:286 "컨테이너 런타임 smoke (entrypoint migrate deploy + 부팅 + HTTP 응답)")는 **실 컨테이너 부팅(gated DB-bound runtime)** 이라 shell 텍스트↔config artifact 의 정적 drift 를 컨테이너 빌드·부팅 없이는 못 잡는다(ci.yml:277 `sh -n` 은 shell 문법 검사만, 계약값 대조 0). daily-test.sh 의 step_eval argv(T-0790)·machine-JSON(T-0791)·HTTP-contract(T-0792)와 distinct 한 **deploy-entrypoint↔build-artifact** 표면이다.

즉 **실 `deploy/docker-entrypoint.sh` 의 두 런타임 계약(prisma 바이너리 경로+migrate deploy 서브커맨드, node dist/src/main 빌드-산출물 경로)을 정적 추출해, 실 build/runtime artifact(`package.json` 의 prisma dependency 배치, `tsconfig.json` 의 outDir, `Dockerfile` 의 ENTRYPOINT·COPY)에서 추출한 정본과 정합임을 단언하는 build-time smoke 가 0 부재** 다. 본 task 는 그 빈 자리를 채운다.

live leg(실 컨테이너·실 docker build·실 prisma migrate·실 NestJS 부팅) 복제 0·non-gated 항상 실행 — 순수 build-time 검증만(파일 read + 정적 텍스트 추출). shell·config·Dockerfile 파일은 읽기만 하고 실행/build/부팅 0.
