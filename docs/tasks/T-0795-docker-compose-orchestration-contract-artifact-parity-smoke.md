# T-0795 — deploy step① docker-compose.yml 오케스트레이션 계약 ↔ 실 build/runtime artifact parity drift-detection non-gated build-time smoke 신설

## Why

PLAN.md §109(🟢 실 평가 e2e, P5) 및 deployment.md 의 배포 step① 은 `deploy/redeploy.sh` 가 매일 밤 `git reset --hard origin/main` 후 **`docker compose up -d --build`** 한 번으로 postgres + NestJS app(web 정적 serve 포함, ADR-0003 monolith)을 함께 띄운다. 그 단일 명령이 읽는 `docker-compose.yml` 은 **무인 배포가 crash-loop 없이 부팅되려면 실 build/runtime artifact 와 정합해야만 하는 풍부한 오케스트레이션 contract** 를 하드코딩한다:

1. **`app.build.dockerfile: Dockerfile`**(39행) — compose 가 app 이미지를 빌드할 때 가리키는 Dockerfile 경로. 이 파일이 실존하고 `ENTRYPOINT ["./deploy/docker-entrypoint.sh"]`(Dockerfile 73행)를 두어야 함.
2. **`app.ports: "${PORT:-3000}:${PORT:-3000}"`(52행) + `environment.PORT: ${PORT:-3000}`(50행)** — 포트 매핑 기본값 `3000` 이 (a) `Dockerfile EXPOSE 3000`(70행), (b) `src/parse-port.ts` 의 `DEFAULT_PORT = 3000`(8행 — 앱이 `process.env.PORT` 미지정시 실제로 listen 하는 포트), (c) `deploy/env.prod.example` 의 `PORT=3000`(18행) 과 **4중 정합** 해야 한다. 어느 하나라도 silent drift 하면 host→container 포트 매핑이 빗나가 무인 배포가 응답 불가(health check fail)가 된다.
3. **`postgres.image: postgres:16-alpine`(14행) + healthcheck `pg_isready -U ${POSTGRES_USER:-...} -d ${POSTGRES_DB:-...}`(27~31행)** — postgres 이미지 태그가 고정 상수이고, healthcheck 가 참조하는 `POSTGRES_USER`/`POSTGRES_DB` env 가 `deploy/env.prod.example`(8·10행)에 존재해야 `depends_on.condition: service_healthy`(45행) 게이트가 valid.
4. **`DATABASE_URL` host=`postgres:5432`** — `deploy/env.prod.example` 의 `DATABASE_URL="postgresql://...@postgres:5432/..."`(15행) host 가 compose 의 **postgres 서비스명**(13행 `postgres:`)이고 port `5432` 가 compose `ports: "5432:5432"`(22행)와 정합해야 app 컨테이너가 DB 에 도달. 서비스명 rename 또는 포트 변경시 app↔DB 연결 silent 단절.

만약 누군가 silent 하게 (a) `app.build.dockerfile` 경로를 바꾸거나 그 Dockerfile 을 지우거나, (b) `PORT` 기본값을 한 곳만 바꾸거나(`parse-port` 만 `8080` 으로 바꾸고 compose/EXPOSE/env 미동기), (c) `postgres` 서비스명을 rename(DATABASE_URL host 와 단절)하거나, (d) healthcheck 가 참조하는 env 가 env.prod.example 에서 빠지면 — 배포 컨테이너가 런타임에 silent 부팅 실패/응답 불가/DB 단절한다. 이는 무인 배포 자율성(REQ-061 smoke-in-CI, REQ-062 배포 산출물 정합)을 깨뜨린다.

직전 sweep 들은 `deploy/` 의 build-time seam 5종을 차례로 닫았다 — daily-test.sh `step_eval` jest argv full-vector(T-0790), 머신 요약 JSON 스키마(T-0791), HTTP step 계약↔NestJS controller route decorator(T-0792), `docker-entrypoint.sh` 런타임 계약↔build artifact(T-0793), `seed-llm-config.sh` SQL/cipher 계약↔prisma schema(T-0794). **T-0793 Follow-up (b1) 는 다음 잔여 distinct build-time seam 후보 "`deploy/redeploy.sh` redeploy 절차 shell↔docker-compose/Dockerfile 정합(docker build·compose up 계약이 실 compose 파일/Dockerfile 과 정합인지 genuine seam HIGH bar 재판정)" 를 명시**했다. 본 task 는 그 후보를 HIGH-bar 로 엄격 재판정해 채택한다.

본 task 의 사전 조사(origin/main a5b7b3bf) 결과 — (1) `redeploy.sh` 자체는 `git reset --hard origin/main` + `docker compose up -d --build` + `docker image prune` 호출만이라 contract 토큰이 얇지만, **그 redeploy 가 호출하는 `docker-compose.yml` 은 풍부한 오케스트레이션 계약을 담고 그 계약이 두드리는 실 artifact 가 전부 실존·안정** 하며, (2) **그 계약을 실 build/runtime artifact 와 대조하는 build-time smoke 는 0 부재** 다:

- **genuine 계약/artifact 실존 확인** (HIGH bar 통과의 핵심 — make-work 가 아님):
  - `docker-compose.yml` 39행 `dockerfile: Dockerfile` ↔ `Dockerfile`(실존, 73행 `ENTRYPOINT ["./deploy/docker-entrypoint.sh"]`·70행 `EXPOSE 3000`).
  - `docker-compose.yml` 50행 `PORT: ${PORT:-3000}` + 52행 `"${PORT:-3000}:${PORT:-3000}"` ↔ `Dockerfile` 70행 `EXPOSE 3000` ↔ `src/parse-port.ts` 8행 `DEFAULT_PORT = 3000`(앱 실 listen 포트) ↔ `deploy/env.prod.example` 18행 `PORT=3000` — 실측 4중 정합.
  - `docker-compose.yml` 14행 `image: postgres:16-alpine` + 27~31행 healthcheck `pg_isready -U ${POSTGRES_USER:-assessment_agent} -d ${POSTGRES_DB:-assessment_agent}` ↔ `deploy/env.prod.example` 8행 `POSTGRES_USER=assessment_agent`·10행 `POSTGRES_DB=assessment_agent`(healthcheck env 가 env 템플릿에 실존).
  - `deploy/env.prod.example` 15행 `DATABASE_URL="postgresql://assessment_agent:...@postgres:5432/assessment_agent?schema=public"` host `postgres` ↔ `docker-compose.yml` 13행 postgres 서비스명, port `5432` ↔ 22행 `"5432:5432"`.
- **build-time cross-artifact smoke 0 부재** — `test/` grep 결과 `docker-compose.yml` 을 읽는 spec 0(compose smoke 파일 부재 실측). CI 런타임 smoke(ci.yml 컨테이너 런타임 smoke)는 **실 컨테이너 부팅(gated runtime)** 이라 compose 계약↔artifact 의 정적 drift 를 컨테이너 빌드·부팅 없이는 못 잡는다. T-0793(docker-entrypoint↔build-artifact)과 distinct 한 **compose-orchestration↔artifact** 표면이다(T-0793 은 entrypoint shell 의 prisma 경로·dist/src/main·Dockerfile ENTRYPOINT/COPY; 본 task 는 compose 의 build.dockerfile·포트 매핑·postgres image/healthcheck·DATABASE_URL host:port).

즉 **실 `docker-compose.yml` 의 오케스트레이션 계약(빌드 dockerfile 경로·포트 매핑 기본값·postgres image/healthcheck env·DATABASE_URL host:port 서비스명 정합)을 정적 추출해, 실 build/runtime artifact(`Dockerfile` 의 EXPOSE/ENTRYPOINT, `src/parse-port.ts` 의 DEFAULT_PORT, `deploy/env.prod.example` 의 PORT/POSTGRES_*/DATABASE_URL)에서 추출한 정본과 정합임을 단언하는 build-time smoke 가 0 부재** 다. 본 task 는 그 빈 자리를 채운다.

live leg(실 `docker compose up` · 실 docker build · 실 컨테이너 부팅 · 실 DB) 복제 0·non-gated 항상 실행 — 순수 build-time 검증만(파일 read + 정적 텍스트/YAML 추출). compose·Dockerfile·parse-port·env 파일은 읽기만 하고 실행/build/부팅 0.

## Acceptance Criteria

신규 파일 `test/smoke/realdata-e2e-docker-compose-orchestration-contract-artifact-parity-drift.smoke-spec.ts` 1개를 추가한다(test-only, src 변경 0, gating/describe.skip 배선 0 — 순수 build-time 파일 read + 정적 텍스트/YAML 추출 검증만, NestJS module import / 부팅 / DB / docker build / compose up 의존 0). 다음을 모두 만족한다:

- [ ] **Happy-path: compose + build/runtime artifact 소스 read + 계약/artifact 추출**: `readFileSync(path.resolve(__dirname, "../../docker-compose.yml"), "utf8")` 로 compose 정본, 그리고 `Dockerfile`·`src/parse-port.ts`·`deploy/env.prod.example` 을 각각 readFileSync 로 읽어 (1) compose 측 오케스트레이션 계약(app.build.dockerfile 경로·`${PORT:-N}` 기본값·postgres.image 태그·healthcheck `pg_isready -U X -d Y` 의 X/Y env 이름·postgres 서비스명·`"5432:5432"` 포트 매핑)을 추출하는 보조 함수, (2) artifact 측(Dockerfile `EXPOSE` 값·`ENTRYPOINT` 행, parse-port `DEFAULT_PORT` 값, env.prod.example `PORT`/`POSTGRES_USER`/`POSTGRES_DB` 값 및 `DATABASE_URL` host:port)을 추출하는 보조 함수를 구현 → 양측 추출 결과가 비어있지 않은 배열/객체임. repo-root 경로는 `path.resolve(__dirname, "../..")` 로 cwd-robust 하게 해석 happy test 1+.
- [ ] **app.build.dockerfile ↔ Dockerfile 실존 정합 수렴(branch — 핵심 불변식 1)**: compose `app.build.dockerfile` 추출값이 `"Dockerfile"`(byte-identical, `toBe`)이고 그 경로의 파일이 실존(`existsSync`/`readFileSync` throw 안 함) AND 그 Dockerfile 이 `ENTRYPOINT` 행을 가짐(compose build 가 valid entrypoint 이미지를 만듦)을 단언 1+ test. dockerfile 경로 rename·파일 삭제 silent drift 검출.
