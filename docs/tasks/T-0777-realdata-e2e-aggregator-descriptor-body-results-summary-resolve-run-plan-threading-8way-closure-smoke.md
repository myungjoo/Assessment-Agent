# T-0777 — realdata-e2e step④ aggregator descriptor-body 합류 8-way single-source closure non-gated build-time smoke 신설

## Why

PLAN.md §109(🟢 실 평가 e2e, P5)의 step④ 멱등 search-or-update 의 build-time 순수 layer 는 **검증된 단일 run plan(`buildRealDataE2eRunPlan(seeds, modelId, run)` → `{pipeline, run}`, T-0597)을 pre-실행 aggregator(`buildRealDataE2eStepArgs(runPlan, activities, results)` → `{evaluation, publish}`, T-0601)에 통째로 넘긴다**. 이 aggregator 는 세 입력 source(`runPlan`·`activities`·`results`)를 받고, T-0776 이 세 번째 source `results` 의 정량 집계 객체 `report.summary` 를 closure 에 묶어 7-way 를 완성했다.

직전 sweep 은 aggregator publish leg 의 **summary(정량 집계 객체)** 와 **marker(3-축)** 를 단일 source 재유도로 묶었으나, publish leg 에는 아직 closure 에 미합류된 distinct 한 출력 surface 가 하나 더 있다 — **`report.descriptor.body`(사람-대면 이슈 본문 렌더)**.

`descriptor.body` 축은 summary 와 distinct 한 표면이다:

- **descriptor.body 축(본 task 의 새 표면)** — `stepArgs.publish.report.descriptor.body: string`(marker 라인 + `formatRealDataResultSummaryLine(summary)` 한 줄 요약 + `renderRealDataResultSummaryMarkdown(summary)` markdown 본문, 세 블록을 빈 줄 1개로 결합, T-0582/T-0642/T-0644 합성)는 **동일 `results`·동일 `runPlan.run` source 로부터 동형 재유도**된다. 즉 `stepArgs.publish.report.descriptor.body` 가 동일 `results`·동일 `runPlan.run` 으로 직접 호출한 `buildRealDataResultIssueCommandPlan(results, runPlan.run).report.descriptor.body` 와 **byte-identical**. summary(정량 집계 객체)는 T-0776 이 묶었으나 **그 summary 가 사람-대면 markdown 본문으로 렌더된 결과(descriptor.body)의 단일-source 재유도 정합은 미합류** — body 는 marker run token·summary line·markdown table 세 블록을 합성한 distinct surface 다.

직전 sibling 들은 이 descriptor.body 축을 byte-identical 재유도로 closure 에 합류시키지 않았다:
- **T-0776 (aggregator 7-way)**: publish leg 의 `report.summary`(=results 재유도 객체)+evaluation inputs/modelId+marker/searchArgv/run-identity 를 단일 (runPlan, activities, results) source 로 수렴 박제. 그러나 **`report.descriptor.body`(=summary 의 렌더 산물)는 credential surface·variance(not.toBe) 로만 사용** — body 의 단일-source `(results, run)` 재유도 byte-identical 정합은 closure 에 미합류.
- **T-0772/0773/0774 (aggregator 3·4·5-way)**: descriptor.body 를 `not.toBe`(results 분포 다르면 body 도 달라야 함) variance 단언으로만 사용 — byte-identical 재유도 미합류.
- **descriptor / descriptor-body-consistency helper spec**: descriptor.body 3블록 구조·렌더 자체는 박제했으나 **aggregator 진입·resolve·post 미합류**(단독 helper 호출만).

본 task 는 그 빈 자리를 채워 **publish leg 의 descriptor.body 렌더 산물을 단일-source `(results, runPlan.run)` 재유도 byte-identical 로 closure 에 묶어**, 검증 source `(runPlan, activities, results)` 세 source 가 aggregator publish leg 의 두 출력 surface(정량 집계 summary + 사람-대면 렌더 body)와 evaluation leg(inputs+modelId), 그리고 marker/searchArgv/run-identity 의 source 임을 resolve+post 까지 묶은 한 chain 으로 박제한다. 단일 source `(runPlan, activities, results, search-stdout, exec-stdout)` 로부터:

1. **publish-leg descriptor-body 렌더 재유도(축 8, 본 task 의 새 표면)** — `stepArgs = buildRealDataE2eStepArgs(runPlan, activities, results)` → `stepArgs.publish.report.descriptor.body` 가 동일 `results`·동일 `runPlan.run` 으로 직접 호출한 `buildRealDataResultIssueCommandPlan(results, runPlan.run).report.descriptor.body` 와 **byte-identical string equal**. 단일 `results`+`run` source 의 사람-대면 본문(marker 라인 + summary 한 줄 + markdown 본문)이 aggregator publish report 로 동형 재유도.
2. **publish-leg results-summary 재유도(축 7, T-0776 cover 영역의 8-way 묶음 항)** — `stepArgs.publish.report.summary` 가 `buildRealDataResultIssueCommandPlan(results, runPlan.run).report.summary` 와 byte-identical deep-equal.
3. **evaluation-leg inputs 재유도 + 페어링(축 6)** — `stepArgs.evaluation.inputs` 가 `buildRealDataEvaluationInputs(activities)` 와 byte-identical, `callArgs[i].input === inputs[i]`.
4. **evaluation-leg modelId thread(축 5)** — 모든 `callArgs[i].options.modelId === runPlan.pipeline.modelId`.
5. **publish-leg 내부 marker 3-축 일치(축 2~4)** — `descriptor.marker === commandArgs.searchQuery === extractSearchMarker(searchArgv)`.
6. **resolve issueNumber + post run-identity(축 1, 종단)** — `resolvePlan = resolveRealDataResultIssueGhCommandPlan(searchStdout, stepArgs.publish.commandArgs)` → `action.update.issueNumber = N` → `outcomeReport = buildRealDataResultOutcomeStepArgs(runPlan, execStdout)` → `{issueNumber, gitSha, dateToken, ...}` 가 동일 runPlan.run 전파.

이 8-way(body 렌더 재유도 + summary 재유도 + inputs 재유도 + modelId + marker 3-축 + resolve issueNumber + post run-identity)가 **세 검증 source `(runPlan, activities, results)`** single-source 로 수렴함이 **search-or-update 멱등성**(REQ-009)·**raw 미보유 평가 입력/결과 집계 정합**(REQ-032)·**결과 리포트 재실행 정합**(REQ-037)의 aggregator-level "정량 집계(summary)+사람-대면 본문(body)+평가 입력(inputs)+평가 정책(modelId)+publish 식별(marker/searchArgv/run-identity)이 같은 세 검증 source 에서 나옴" 의 종단 닫음이다. **publish leg 의 두 출력 surface(summary 객체 + body 렌더)가 모두 단일-source 재유도로 묶이는 slice** 다.

gap 확인(git grep, origin/main 7339b67d): `for f in test/smoke/realdata-e2e*.smoke-spec.ts; do (buildRealDataE2eStepArgs AND descriptor.body byte-identical 재유도(toEqual/toBe vs buildRealDataResultIssueCommandPlan(...).report.descriptor.body) AND resolveRealDataResultIssueGhCommandPlan 동시 실 호출) 여부; done` — **0 파일**(직전 fire 실측 확인 — T-0776/0774/0773/0772 는 descriptor.body 를 variance(not.toBe)·credential surface 로만 사용·byte-identical 재유도 미합류, descriptor helper spec 은 aggregator·resolve·post 미합류). `git log origin/main` 동일 영역 박제 commit 0.

live leg(실 prisma·실 collectForPerson·실 github.com fetch·실 LLM scoring·실 gh CLI 실행·DB·LAN gate) 복제 0·non-gated 항상 실행 — 순수 build-time in-memory 검증만.
