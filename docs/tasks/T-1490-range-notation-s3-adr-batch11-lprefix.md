# T-1490 — 범위 표기 규약 축 S3 batch 11 — `L` 축 ADR 3 파일 (`ADR-0002` · `ADR-0027` · `ADR-0029`) `R5` · `R4` 정규화

## Why

[REQ-COVERAGE-AUDIT.md](../use-cases/REQ-COVERAGE-AUDIT.md) `§ 12.87` (S3 batch 10) 의 **파생 영향 (1)** 이 **1 순위** 로 지목한 **S3 batch 11 = `L` 잔존 7 ADR 중 `ADR-0002` (1 행 / 7 좌표) · `ADR-0027` (2 행 / 3 좌표) · `ADR-0029` (2 행 / 2 좌표)** 를 집행한다. `§ 12.83` AC 6 이 en dash 축 마감을 선언했으므로 후보는 여전히 **`L` 축 단일 축** 이며, 규범 정본은 `§ 12.76` 조문 `R1` ~ `R7`, 판정 선례는 `§ 12.82` AC 3 (`R5` 자기 소멸 · 규약 범위 밖 문서 좌표) · `§ 12.84` AC 3 (병기 4 변형) · `§ 12.85` AC 3 (가운뎃점 · prefix 생략 · 구분자 보존) · `§ 12.86` AC 3 (식별자 범위 3 분해 · 혼합 병기 · 반복 label 동시 정정) · `§ 12.87` AC 3 (label 전체 좌표 · 좌표 약칭화 · 파일명 결합 label · 좌표/식별자 혼합 슬래시) 를 승계한다.

본 slice 가 새로 여는 판정 축은 셋이다 — (가) **7 좌표 슬래시 체인**: `ADR-0002`:121 은 한 행이 `L48 / L50 / L51 / L52 / L55 / L66 / L67` **7 단일 행 좌표** 를 슬래시로 잇고, 그 뒤 em dash 너머에 **같은 길이의 REQ 슬래시 목록** (`REQ-029 / 031 / ...`) 이 **위치 대응** 으로 붙는다. `§ 12.85` 한계 4 가 선례로만 갖고 있는 **단위어 부착 규칙** (묶음당 1 회 vs 좌표마다) 이 본 batch 최대 부하로 시험되며, 부착 방식이 좌표 ↔ REQ 의 위치 대응 가독을 해치지 않는지가 쟁점이다. (나) **자기 문서 내부 좌표 첫 등장**: `ADR-0029`:39 의 `본 L37` 은 다른 파일이 아니라 **그 ADR 자신의 37 행** 을 가리키며, 문맥이 이미 완료된 task 기록 (`T-0255 에서 수행` closeout) 이라 `R7` (시점 기록) 면제 여지가 함께 걸린다 — `§ 12.80` 의 `ADR-0008`:149 이후 `R7` 면제가 실제로 성립할 두 번째 후보다. 자기 참조 좌표는 그 문서 자신을 편집하면 값이 흔들린다는 고유 취약성도 한계로 남긴다. (다) **`R5` 존치 조건의 3 분해 정면 의존 + 기처리 파일 재방문**: `ADR-0029` 의 유일한 raw `~` 는 `REQ-005~010` 이라 `§ 12.86` AC 3 ① 의 **좌표 / 수량 / 식별자 3 분해** 결과에 따라 존치 성립 여부가 갈리는 첫 파일이고, `ADR-0002` 는 **S3 batch 1 (`§ 12.78`) 에서 이미 `R1` 축으로 정정된 파일을 다른 축으로 재방문** 하는 첫 사례라 `§ 12.76` AC 3 ③ 의 한정 소급 원칙과 충돌하지 않는지 별도 확인이 필요하다.

`CLAUDE.md` §3.1 **rule 5** (기존 `docs/decisions/*` 본문의 **비-결정 수정** = `direct`) 의 **열한 번째** 적용 선례이며, 편집 대상은 `L` prefix 제거 + 단위어 부착 + 구분자 보존에 한정되고 ADR 의 결정 실질은 무편집이다.
