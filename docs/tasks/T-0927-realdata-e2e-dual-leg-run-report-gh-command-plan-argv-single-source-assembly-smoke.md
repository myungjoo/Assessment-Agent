# T-0927 — realdata-e2e dual-leg run report gh-command-plan argv single-source assembly non-gated build-time smoke 신설

## Why

PLAN.md 109행 (🟢 실 평가 e2e, P5) step④ (daily-test dual-leg run 결과 rolling-issue 박제) chain 의 **종단 gh-command-plan 컴포저 seam — 산출 `plan.argv` ↔ single-source gh-argv 빌더 정합 seam** 이 아직 어떤 smoke 에도 chain 그물로 묶이지 않았다. `resolveRealDataDailyStepDualLegRunReportIssueGhCommandPlan(stdout, commandArgs)`(T-0902) 은 search stdout + 명령-args 묶음을 입력 받아 `{action, argv}` 종단 실행 plan 을 산출하는 순수 컴포저로, 그 `argv` 는 내부적으로 `buildRealDataDailyStepDualLegRunReportIssueGhArgv(action, commandArgs)`(T-0899) 를 위임 호출해 얻는다. 그러나 `git grep` 결과 이 execute-side gh-argv 빌더(`buildRealDataDailyStepDualLegRunReportIssueGhArgv`, create → `gh issue create` argv / update → `gh issue edit <N>` argv 를 산출)를 **직접 참조하는 smoke 파일은 0개**이며, dual-leg 축에는 **gh-command-plan-assembly smoke 자체가 존재하지 않는다**(summary 축은 `realdata-e2e-result-issue-gh-command-plan-assembly.smoke-spec.ts` 로 자기 gh-argv 빌더를 직접 smoke 로 봉합했으나 dual-leg 축은 그 mirror 를 아직 안 만듦).

직전 형제 T-0924·T-0925·T-0926 은 **value-consistency 3-seam**(execute-leg output↔stdout·search-leg hits↔stdout·종단 컴포저 report↔input)을 닫아 dual-leg run report 의 **파서·컴포저 value-정합 축을 종결**했다. 그러나 그 값-정합 축은 **파싱/조립 산출물의 값 재유도**에 초점이고, **종단 gh-command-plan 컴포저가 산출한 실행 argv 벡터 자체** — create 분기(`["issue","create","--title",title,"--body",body, ...labels flag-pair 전개]`)와 update 분기(`["issue","edit",String(issueNumber),"--title",title,"--body",body]`) — 가 single-source gh-argv 빌더 산출과 원소·순서·labels 전개·issueNumber 문자열화 면에서 byte-identical 하게 정합하는지는 어느 smoke 도 chain 그물로 검증하지 않았다.

기존 형제 smoke 중 execute-side argv 를 다룬 것은 T-0920(edit-argv execute-side)뿐이며, 이는 **update/edit 분기의 `plan.argv[2]===String(N)` 한 원소** 만 자산화하고 **create 분기 argv(gh issue create + labels flag-pair 전개) 전체 벡터** 는 어느 smoke 도 자산화하지 않았다. 즉 **gh-command-plan 컴포저가 silent 하게 create argv 원소를 drift 시키거나 labels flag-pair 순서를 뒤집거나 issueNumber 를 오문자열화하거나 argv 원소를 누락/재정렬해도**, 그 손상 plan 이 실 `execFile('gh', argv)` live wiring 으로 새기 전에 build-time smoke 로 잡히지 않았다(plan.argv 를 single-source 빌더 산출과 대조하는 단언이 어느 smoke 에도 없으므로).

본 task 는 그 **종단 gh-command-plan seam** 을 닫는다. chain: (1) 두 leg outcome + run → report(컴포저) → descriptor → commandArgs 를 통과시켜 유효 `RealDataDailyStepDualLegRunReportIssueCommandArgs` 를 얻고, (2) 후보 0건 search stdout(`"[]"` 또는 marker 미포함) 및 후보 1+건 search stdout(marker 포함)을 각각 `resolveRealDataDailyStepDualLegRunReportIssueGhCommandPlan(stdout, commandArgs)` 로 통과시켜 `{action, argv}` plan 을 산출한 뒤, plan.argv 가 `buildRealDataDailyStepDualLegRunReportIssueGhArgv(plan.action, commandArgs)`(컴포저 재호출 없이 빌더 직접 호출) 산출과 **byte-identical**(원소·순서·labels flag-pair 전개·issueNumber 문자열화) 정합하고 plan.action 이 hits 로부터 재유도한 action(빈→create·1+→최소 number update)과 일치함을 박제한다 — summary 축 `realdata-e2e-result-issue-gh-command-plan-assembly.smoke-spec.ts` gh-command-plan argv single-source assembly 커버리지의 dual-leg mirror.
