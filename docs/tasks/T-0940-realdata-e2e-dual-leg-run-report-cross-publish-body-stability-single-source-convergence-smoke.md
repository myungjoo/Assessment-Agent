# T-0940 — realdata-e2e dual-leg run report cross-publish body stability single-source convergence non-gated smoke

## Why

PLAN.md 109행 (🟢 실 평가 e2e, P5) step④ (daily-test dual-leg run 결과 rolling-issue 멱등 박제) chain 의 **같은 run 을 여러 밤 연속 publish 할 때, 사람이 이슈 안에서 읽는 rolling-issue 의 본문(`descriptor.body` = `--body` argv 값, marker 라인 포함)이 1차 create publish 와 그 이후 모든 update publish 에서 어긋나지 않고 안정하며, 나아가 그 본문이 매 publish 마다 단일 source(commandArgs)로부터 재-정규화(re-emit)되어 search-hit 의 body 필드 종속이 아님(issueNumber 처럼 threaded 되지 않아 오염된 본문이 self-heal)** — 이 아직 어떤 smoke 에도 chain 그물로 묶이지 않았다.

REQ-009 멱등("동일 run 의 기존 이슈를 찾아 갱신, 중복 생성 안 함")의 cross-publish 안정성은 **여러 매체(medium)** 위에 얹혀 있고, 그 중 사람-향(向) 축은 지금까지 네 개가 봉합됐다:

- **title 축 — 사람 제목(T-0939 이 봉합)** — 사람이 이슈 목록에서 먼저 스캔하는 `--title` 이 1차 create 와 이후 모든 update 에서 byte-identical.
- **url 축 — 사람 링크(T-0937 permalink)** — 사람이 브라우저로 여는 `outcome.url` 이 cross-publish byte-identical.
- **marker 축 — 검색 anchor(T-0938)** — 다음 밤 rolling-issue 를 재발견하는 `searchQuery`(=marker) 와 body 안의 marker 라인 round-trip.
- **issueNumber 축 — 편집 대상 threaded(T-0922)** — 1차 create-output 의 M 이 이후 밤 hit 로 threaded.

**body 축 — 사람 본문(본 task 가 봉합)** — 사람이 제목을 스캔하고 링크를 연 뒤 **실제로 이슈 안에서 읽는 것은 본문(dual-leg run report 콘텐츠)** 이다. rolling-issue 멱등이 성립하려면 1차 밤에 create 로 박은 본문이 2차·3차 밤의 update 후에도 **같은 본문**(같은 run 의 canonical report content)이어야 한다 — 그래야 갱신마다 본문이 조용히 흔들리거나 다른 밤의 내용으로 오염되지 않는다. `descriptor.body` 는 run 식별(runToken=dateToken@gitSha)에서 파생된 marker 라인을 **포함** 하고 leg outcome/timestamp 를 혼입하지 않아, 같은 run 이면 밤마다 같은 본문이다.

그리고 이 body 안정성에는 title(T-0939)과 **동형** 인 load-bearing 성질이 있다: **body 는 search-hit 에서 threaded 되지 않는다.** issueNumber(republish T-0922)는 1차 create-output 의 M 이 2차 search-hit 로 다시 관통해 update argv[2] 로 threaded 되지만, **body 는 매 publish 마다 commandArgs.updateArgs.body(=descriptor.body, 단일 source)로부터 재-발행(re-emit)** 된다. 즉 만약 사람이 GitHub 에서 rolling-issue 본문을 손으로 바꿔도(search-hit 의 body 필드가 오염돼도, 단 marker 라인만 남기면 재발견은 성립 — T-0938), 다음 밤 update publish 는 그 오염된 hit.body 를 이어받지 않고 **descriptor.body 로 다시 정규화** 한다 — 본문이 단일 source 로 self-heal 된다. 이 "body 는 threaded 아니라 re-emit" 성질이 cross-publish 본문 무결성의 핵심 근거다.

그러나 이 **cross-publish body stability single-source(및 hit-오염 재정규화)** 를 어느 smoke 도 검증하지 않는다:

- 형제 T-0931(body cross-branch)은 **한 chain 내부** 에서 create argv `--body`(빈 search 분기)와 update argv `--body`(marker-hit 분기)이 단일 `descriptor.body` 로부터 byte-identical 함만 자산화한다 — **여러 publish 에 걸친**(여러 밤 재조립) 안정성·hit.body 오염 시 재정규화는 대상이 아니다(intra-chain ≠ cross-publish).
- 형제 marker(T-0938)는 body 중 **marker 라인** 만(searchQuery cross-publish 안정 + body-marker round-trip)을 자산화한다 — body 라인 하나(검색 anchor)의 round-trip 이지 **전체 body 콘텐츠** 의 cross-publish 안정성·재정규화는 대상이 아니다(marker 라인 ⊂ body).
- 형제 title(T-0939)은 사람-제목(`--title`)의 cross-publish 안정성 + 재정규화만 자산화한다 — title 은 한 줄 제목, body 는 multi-line 본문(marker 라인 포함)이라 다른 field·다른 argv flag·다른 역할(제목 스캔 ≠ 본문 열람). body 는 title 의 content-medium 짝.
- 형제 republish(T-0922)는 issueNumber M 이 hit 로 threaded 됨만 자산화한다 — body 가 threaded **아님**(re-emit)은 그 거울상 성질인데(title 과 동형) body 축에서 아무도 단언하지 않았다.

본 task 는 그 **cross-publish body stability + hit-오염 재정규화 seam** 을 닫는다 — cross-publish 안정 quadrilogy 의 사람-본문 짝(그리고 body 가 issueNumber 처럼 threaded 아니라 단일 source re-emit 임을 못 박는 축). chain: 두 leg outcome + run → report → descriptor → commandArgs 를 통과시켜 사람-본문 `descriptor.body`(=`--body` argv 값, marker 라인 포함)를 얻고, (1차) 빈 search(`"[]"`)로 create plan → create argv 의 `--body` 다음 원소, (2·3차) 1차 create body 를 그대로 담은 search-hit → resolve(marker 매칭 → update) → update plan 의 `--body` 다음 원소를 산출한 뒤, 세 publish 의 `--body` 값이 모두 byte-identical(=descriptor.body=createArgs.body=updateArgs.body) AND hit.body 를 오염시켜도(marker 라인 유지) update argv 의 `--body` 가 여전히 descriptor.body(단일 source)로 재정규화됨을 박제한다.

issue-still-relevant 확인(2026-07-12): `ls test/smoke | grep dual-leg | grep -iE "cross-publish"` = marker/url/title stability 3개(body 미봉합), `ls test/smoke | grep body` = `body-cross-branch`(T-0931, intra-chain)·`descriptor-body-confluence` 등 — cross-publish 전체 body 안정성/재정규화 0개. `git log origin/main` 동일 영역(dual-leg cross-publish body stability smoke) 박제 commit 0. descriptor 빌더(body=marker 라인 포함 run 파생)·command-args 빌더(createArgs.body/updateArgs.body=descriptor.body)·종단 컴포저(resolve, update argv body=updateArgs.body 이 hit.body 아님) 배선은 이미 main 에 박제됨 — 본 task 는 그 배선을 **다시 만들지 않고** 여러 publish 의 --body 상호 동일성 + hit-오염 재정규화를 대조하는 **smoke 그물만** 신설.
