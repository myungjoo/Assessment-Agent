# T-0781 — realdata-e2e step④ aggregator resolve-argv 위치-정합 합류 12-way single-source closure non-gated build-time smoke 신설

## Why

PLAN.md §109(🟢 실 평가 e2e, P5)의 step④ 멱등 search-or-update 의 build-time 순수 layer 는 **검증된 단일 run plan(`buildRealDataE2eRunPlan(seeds, modelId, run)` → `{pipeline, run}`, T-0597)을 pre-실행 aggregator(`buildRealDataE2eStepArgs(runPlan, activities, results)` → `{evaluation, publish}`, T-0601)에 통째로 넘긴다**. 이 aggregator 는 세 입력 source(`runPlan`·`activities`·`results`)를 받고, T-0778~0780 sweep 이 publish leg 의 **command-args 객체 surface 세 개(body·title·labels)** 를 모두 단일 source 산출과 byte-identical/고정-상수로 closure 에 묶어 11-way 를 완성했다.

직전 sweep 들은 aggregator publish leg 의 **command-args 객체 필드값**(`createArgs/updateArgs.{title,body}`·`createArgs.labels`)을 단일 source 와 묶었다. 그러나 그 필드값들이 실제로 live runner 가 `execFile('gh', argv)` 로 거는 **gh CLI 인자-벡터(argv) 의 정확한 위치**로 조립됨은 아직 convergence closure 에 미합류된 distinct 표면이다 — `resolvePlan.argv` 는 `resolveRealDataResultIssueGhCommandPlan(searchStdout, stepArgs.publish.commandArgs)` 이 `buildRealDataResultIssueGhArgv(action, commandArgs)` 위임으로 조립한 **최종 실행 벡터**다(`realdata-e2e-result-issue-gh-argv.ts`).

`resolvePlan.argv` 위치-정합 축은 command-args 객체 surface(T-0778~0780)와 distinct 한 표면이다:

- **resolve-argv 위치-정합 축(본 task 의 새 표면)** — `resolvePlan.argv: string[]`(`buildRealDataResultIssueGhArgv(action, commandArgs)`, T-0585)는 command-args 필드값을 **gh CLI 인자 위치**로 조립한다:
  - **update 분기**(검색 hit 1+) — `argv == ["issue", "edit", String(N), "--title", updateArgs.title, "--body", updateArgs.body]`(gh-argv 148행). 즉 `argv[0]=="issue"`, `argv[1]=="edit"`, `argv[2]==String(N)`, `argv[3]=="--title"`, `argv[4]==updateArgs.title`, `argv[5]=="--body"`, `argv[6]==updateArgs.body`.
  - **create 분기**(검색 hit 0) — `argv == ["issue", "create", "--title", createArgs.title, "--body", createArgs.body, "--label", "realdata-e2e", "--label", "result"]`(gh-argv 116·119행). labels 는 각 원소를 `"--label", <label>` flag-pair 로 순서 보존 전개. 즉 `argv[0..1]==["issue","create"]`, `argv[3]==createArgs.title`, `argv[5]==createArgs.body`, `argv[6..]==["--label","realdata-e2e","--label","result"]`.
  - 이 argv 값-위치들은 모두 closed command-args surface(`updateArgs/createArgs.{title,body}`·`createArgs.labels`) 의 단일-source 필드값을 **byte-identical** 로 운반한다. command-args 객체는 "필드"였고 argv 는 그 필드들이 **실 gh CLI 호출 위치로 조립된 벡터** — distinct surface. 이 "argv 위치별 값 == aggregator command-args 단일-source 필드값 byte-identical" 정합은 aggregator+resolve+post closure 에 미합류.

직전 sibling 들은 이 resolve-argv 위치-정합 축을 convergence closure 에 합류시키지 않았다:
- **T-0780 (aggregator 11-way)**: publish leg 의 `commandArgs.createArgs.labels`(=고정 상수) + command-args title/body 두 경로 + descriptor.{title,body} 재유도 + summary + inputs/modelId + marker/searchArgv/run-identity 를 단일 (runPlan, activities, results) source 로 수렴 박제. 그러나 **`resolvePlan.argv` 위치-정합(argv[3]==title·argv[5]==body·labels flag-pair 전개)은 convergence closure 에 미합류** — 그 spec 안 argv 참조는 `argv[0]=="issue"`·`argv[1]=="edit"` 동사 shape 단언(397~398행)과 `argv.join(" ")` credential-negative(1108행)일 뿐, argv 위치별 값이 단일-source command-args 필드와 byte-identical 함을 묶은 단언 0.
- **T-0779/0778 (aggregator 10·9-way)**: 동일하게 argv 는 동사 shape + credential-negative 만.
- **T-0777~0772 (aggregator 8~triple-boundary)**: searchArgv(--match marker)만 합류 — resolve 결과 argv 위치-정합 미합류.
- **gh-argv self-guard**: `assertRealDataResultIssueGhArgvPreservesCommandArgs`(T-0650/0652, gh-argv 130·161행)가 빌더 내부 self-wire 로 argv↔command-args round-trip 을 박제했으나 **aggregator(`buildRealDataE2eStepArgs`) 진입·resolve·post 미합류**(빌더 단독 self-guard).

본 task 는 그 빈 자리를 채워 **publish leg 의 command-args 필드값들이 resolve 가 조립한 실 gh CLI argv 위치로 byte-identical 운반됨을 같은 aggregator 산출 + descriptor 재유도와 묶어 closure 에 합류**시킨다. 단일 source `(runPlan, activities, results, search-stdout, exec-stdout)` 로부터:

1. **resolve-argv update-분기 위치-정합(축 12, 본 task 의 새 표면)** — `stepArgs = buildRealDataE2eStepArgs(runPlan, activities, results)`, search hit N → `resolvePlan = resolveRealDataResultIssueGhCommandPlan(searchStdout, stepArgs.publish.commandArgs)` → `resolvePlan.argv` 가 `["issue","edit",String(N),"--title",updateArgs.title,"--body",updateArgs.body]` 와 byte-identical(원소·순서·길이). 특히 `argv[2]==String(N)`(resolve 가 찾은 issueNumber 문자열화), `argv[4]==stepArgs.publish.commandArgs.updateArgs.title`(=descriptor.title), `argv[6]==stepArgs.publish.commandArgs.updateArgs.body`(=descriptor.body).
2. **resolve-argv create-분기 위치-정합(축 12 create leg)** — search hit 0(`[]`) → `resolvePlan.argv` 가 `["issue","create","--title",createArgs.title,"--body",createArgs.body,"--label","realdata-e2e","--label","result"]` 와 byte-identical. 특히 `argv[3]==createArgs.title`, `argv[5]==createArgs.body`, labels 가 `--label`,값 flag-pair 로 순서 보존 전개(`createArgs.labels = ["realdata-e2e","result"]` → argv 6~9).
3. **publish-leg command-args-labels 고정-상수 일치(축 11, 11-way 묶음 항)** — `stepArgs.publish.commandArgs.createArgs.labels` 가 `["realdata-e2e","result"]` deep-equal.
4. **publish-leg command-args-title/body 두 경로 일치(축 9~10)** — `createArgs/updateArgs.title` 가 `descriptor.title`, `createArgs/updateArgs.body` 가 `descriptor.body` 와 byte-identical.
5. **publish-leg descriptor-{title,body}·summary 재유도(축 6~8)** — `descriptor.{title,body}`·`report.summary` 가 `buildRealDataResultIssueCommandPlan(results, runPlan.run).report.{descriptor.{title,body},summary}` 와 byte-identical.
6. **evaluation-leg inputs 재유도 + 페어링 + modelId thread(축 4~5)** — `evaluation.inputs == buildRealDataEvaluationInputs(activities)`, `callArgs[i].input === inputs[i]`, `callArgs[i].options.modelId === runPlan.pipeline.modelId`.
7. **publish-leg marker 3-축 일치(축 2~3)** — `descriptor.marker === commandArgs.searchQuery === extractSearchMarker(searchArgv)`.
8. **resolve issueNumber + post run-identity(축 1, 종단)** — `resolvePlan.action.update.issueNumber = N` → `outcomeReport = buildRealDataResultOutcomeStepArgs(runPlan, execStdout)` → `{issueNumber, gitSha, dateToken, ...}` 가 동일 runPlan.run 전파.

이 12-way(resolve-argv update/create 위치-정합 + command-args labels 고정상수 + command-args title/body 두 경로 + descriptor.{title,body} 재유도 + summary 재유도 + inputs 재유도 + modelId + marker 3-축 + resolve issueNumber + post run-identity)가 **세 검증 source `(runPlan, activities, results)`** single-source 로 수렴함이 **search-or-update 멱등성**(REQ-009 — 검색 결과에 따라 같은 단일-source 필드값이 create/edit argv 위치로 동형 조립)·**raw 미보유 평가 입력/결과 집계 정합**(REQ-032)·**결과 리포트 재실행 정합**(REQ-037)의 aggregator-level "command-args 필드값이 실 gh CLI 인자-벡터 위치로 byte-identical 조립됨(create/update 두 분기)이 같은 세 검증 source 의 산물" 의 종단 닫음이다. **command-args 객체 surface(필드)와 resolve-argv surface(실행 벡터 위치)가 모두 단일-source 로 묶이는 slice** 다.

gap 확인(git grep, origin/main c8878e8b): `for f in test/smoke/realdata-e2e*.smoke-spec.ts; do (buildRealDataE2eStepArgs AND resolvePlan.argv 위치별 값 정합) 여부; done` — aggregator+resolvePlan.argv 참조 smoke 는 **9파일** 이나 그 안 argv 참조는 모두 `argv[0]=="issue"`·`argv[1]=="edit"` 동사 shape + `argv.join(" ")` credential-negative 일 뿐 **argv 위치별 title/body/label 값 == 단일-source command-args 필드 byte-identical 축은 미합류**. `aggregator-*resolve-argv-positional* smoke 파일 부재` + `git log origin/main` 동일 영역 박제 commit 0.

live leg(실 prisma·실 collectForPerson·실 github.com fetch·실 LLM scoring·실 gh CLI 실행·DB·LAN gate) 복제 0·non-gated 항상 실행 — 순수 build-time in-memory 검증만.
