# T-0780 — realdata-e2e step④ aggregator command-args-labels 합류 11-way single-source closure non-gated build-time smoke 신설

## Why

PLAN.md §109(🟢 실 평가 e2e, P5)의 step④ 멱등 search-or-update 의 build-time 순수 layer 는 **검증된 단일 run plan(`buildRealDataE2eRunPlan(seeds, modelId, run)` → `{pipeline, run}`, T-0597)을 pre-실행 aggregator(`buildRealDataE2eStepArgs(runPlan, activities, results)` → `{evaluation, publish}`, T-0601)에 통째로 넘긴다**. 이 aggregator 는 세 입력 source(`runPlan`·`activities`·`results`)를 받고, T-0779 이 publish leg 의 실행-인자 식별 surface `commandArgs.{createArgs,updateArgs}.title` 을 단일 source 산출 `descriptor.title` 와 byte-identical 로 closure 에 묶어 10-way 를 완성했다.

직전 sweep(T-0779)은 aggregator publish leg 의 **command-args title 두 실행 경로(`createArgs.title`·`updateArgs.title`)** 를 같은 단일 source `descriptor.title` 와 byte-identical 로 묶었다. 그 전 T-0778 은 같은 두 경로의 **body** 를 `descriptor.body` 와 묶었다. 그러나 command-args 의 **분류(labels) surface** 인 `createArgs.labels` 은 아직 convergence closure 에 미합류된 distinct 표면이다 — labels 는 gh issue create 명령에서 title(식별)·body(내용)와 서로 다른 인자(`--label`)이며, descriptor 가 아니라 **빌더 내부의 고정 결정론 상수 `RESULT_ISSUE_LABELS = ["realdata-e2e","result"]`** 에서 나온다.

`commandArgs.createArgs.labels` 축은 `commandArgs.{createArgs,updateArgs}.title`(T-0779)·`.body`(T-0778) 와 distinct 한 표면이다:

- **command-args-labels 축(본 task 의 새 표면)** — `stepArgs.publish.commandArgs.createArgs.labels: string[]`(`buildRealDataResultIssueCommandArgs(descriptor)`, T-0583 이 createArgs 에만 `[...RESULT_ISSUE_LABELS]` 복제본 전달 — `realdata-e2e-result-issue-command-args.ts` 64행 상수·133행 복제)는 **descriptor 와 무관한 고정 결정론 분류 상수 `["realdata-e2e","result"]` 와 byte-identical**(deep-equal). 즉 live runner 가 실제로 `gh issue create --label realdata-e2e --label result` 로 거는 **이슈 분류 surface** 가 항상 같은 고정 분류 라벨 집합을 운반한다. title·body 는 `descriptor`(results+run 종속) 에서 유도되지만, `createArgs.labels` 은 **빌더 보유 상수**(results·run·activities 어느 입력에도 비종속) — 그래서 두 chain(results_A vs results_B, run_A vs run_B)에서도 항상 동일해야 한다. 또한 매 호출 **새 배열 복제본**(133행 `[...RESULT_ISSUE_LABELS]`)이라 무공유다. `updateArgs` 에는 labels 가 없다(gh issue edit 은 본문/제목만 갱신 — labels 는 create 시 1회 분류). 이 "createArgs.labels == 고정 상수 == command-plan 경유 재유도 == 입력-비종속 + 무공유" 정합은 aggregator+resolve+post closure 에 미합류.

직전 sibling 들은 이 command-args-labels 축을 convergence closure 에 합류시키지 않았다:
- **T-0779 (aggregator 10-way)**: publish leg 의 `commandArgs.{createArgs,updateArgs}.title`(=descriptor.title byte-identical, 두 실행 경로) + command-args body + descriptor.{title,body} 재유도 + summary + inputs/modelId + marker/searchArgv/run-identity 를 단일 (runPlan, activities, results) source 로 수렴 박제. 그러나 **`commandArgs.createArgs.labels`(=고정 분류 상수가 실 gh `--label` 인자로 들어간 분류 surface)는 convergence closure 에 미합류** — 그 spec 안 labels 참조는 무공유 보조 단언(직접 호출 commandArgs 와 deep-equal 이되 `not.toBe` — 새 배열)일 뿐, labels byte-identical 재유도/고정-상수 일치/입력-비종속 변별 단언 0.
- **T-0778 (aggregator 9-way)**: command-args body 두 경로만 합류 — labels 는 동일한 무공유 보조 수준.
- **T-0777/0776/0775/0774 (aggregator 8·7·6·5-way)**: command-args 의 body·searchQuery·marker 축만 합류 — `createArgs.labels` 미합류.
- **command-args-labels-title self-guard smoke**: `assertRealDataResultIssueCommandArgsLabelsTitleConsistent`(T-0651) 가 빌더 내부 self-wire 로 labels↔고정상수 일치를 박제했으나 **aggregator(`buildRealDataE2eStepArgs`) 진입·resolve·post 미합류**(빌더 단독 self-guard 또는 command-args helper-level 만).

본 task 는 그 빈 자리를 채워 **publish leg 의 분류 surface(createArgs.labels)를 같은 aggregator 산출 + 고정 결정론 상수 + command-plan 재유도와 byte-identical 로 closure 에 묶어**, 검증 source `(runPlan, activities, results)` 세 source 가 aggregator publish leg 의 다섯 출력 surface(정량 집계 summary + 사람-대면 렌더 descriptor.body + 식별 제목 descriptor.title + 실행-인자 두 경로 body·title + 분류 라벨 command-args labels)와 evaluation leg(inputs+modelId), 그리고 marker/searchArgv/run-identity 의 source 임을 resolve+post 까지 묶은 한 chain 으로 박제한다. 단일 source `(runPlan, activities, results, search-stdout, exec-stdout)` 로부터:

1. **publish-leg command-args-labels 고정-상수 일치(축 11, 본 task 의 새 표면)** — `stepArgs = buildRealDataE2eStepArgs(runPlan, activities, results)` → `stepArgs.publish.commandArgs.createArgs.labels` 가 **고정 결정론 상수 `["realdata-e2e","result"]` 와 byte-identical deep-equal**(`toEqual`). 즉 gh issue create --label 경로 분류 라벨이 항상 같은 고정 분류 집합을 운반.
2. **publish-leg command-args-labels 단일-source 재유도 deep-equal(축 11 재유도)** — 동일 `results`·동일 `runPlan.run` 으로 직접 호출한 `buildRealDataResultIssueCommandPlan(results, runPlan.run).commandArgs.createArgs.labels` 가 `stepArgs.publish.commandArgs.createArgs.labels` 와 **byte-identical deep-equal**(`toEqual`) 이되 **referential 분리**(`not.toBe`, 무공유 새 배열). 재유도는 command-plan 경유(`buildRealDataResultIssueCommandArgs` 직접 호출 금지 — aggregator 가 실제 거치는 동일 위임 경로 SSOT).
3. **publish-leg command-args-title 두 경로 일치(축 10, T-0779 cover 영역의 11-way 묶음 항)** — `createArgs.title` 와 `updateArgs.title` 가 둘 다 `descriptor.title` 와 byte-identical(`toBe`).
4. **publish-leg command-args-body 두 경로 일치(축 9)** — `createArgs.body` 와 `updateArgs.body` 가 둘 다 `descriptor.body` 와 byte-identical(`toBe`).
5. **publish-leg descriptor-{title,body} 렌더 재유도(축 7~8)** — `descriptor.{title,body}` 가 `buildRealDataResultIssueCommandPlan(results, runPlan.run).report.descriptor.{title,body}` 와 byte-identical(`toBe`).
6. **publish-leg results-summary 재유도(축 6)** — `report.summary` 가 동 command-plan `.report.summary` 와 byte-identical deep-equal(`toEqual`).
7. **evaluation-leg inputs 재유도 + 페어링(축 5)** — `evaluation.inputs` 가 `buildRealDataEvaluationInputs(activities)` 와 byte-identical, `callArgs[i].input === inputs[i]`.
8. **evaluation-leg modelId thread(축 4)** — 모든 `callArgs[i].options.modelId === runPlan.pipeline.modelId`.
9. **publish-leg 내부 marker 3-축 일치(축 2~3)** — `descriptor.marker === commandArgs.searchQuery === extractSearchMarker(searchArgv)`.
10. **resolve issueNumber + post run-identity(축 1, 종단)** — `resolvePlan = resolveRealDataResultIssueGhCommandPlan(searchStdout, stepArgs.publish.commandArgs)` → `action.update.issueNumber = N` → `outcomeReport = buildRealDataResultOutcomeStepArgs(runPlan, execStdout)` → `{issueNumber, gitSha, dateToken, ...}` 가 동일 runPlan.run 전파.

이 11-way(command-args labels 고정-상수 일치+재유도 + command-args title 두 경로 + command-args body 두 경로 + descriptor.{title,body} 재유도 + summary 재유도 + inputs 재유도 + modelId + marker 3-축 + resolve issueNumber + post run-identity)가 **세 검증 source `(runPlan, activities, results)`** single-source 로 수렴함이 **search-or-update 멱등성**(REQ-009 — 분류 라벨이 결정론 고정 상수)·**raw 미보유 평가 입력/결과 집계 정합**(REQ-032)·**결과 리포트 재실행 정합**(REQ-037)의 aggregator-level "정량 집계(summary)+사람-대면 본문(descriptor.body)+식별 제목(descriptor.title)+실행 인자 본문·제목(command-args body·title 두 경로)+분류 라벨(command-args labels 고정 상수)+평가 입력(inputs)+평가 정책(modelId)+publish 식별(marker/searchArgv/run-identity)이 같은 세 검증 source 에서 나옴(단 labels 는 입력-비종속 고정 상수)" 의 종단 닫음이다. **publish leg 의 다섯 출력 surface(summary 객체 + descriptor.body 렌더 + descriptor.title 식별 + command-args 두 경로 body·title + command-args labels 분류)가 모두 단일-source 재유도/고정-상수 일치로 묶이는 slice** 다.
