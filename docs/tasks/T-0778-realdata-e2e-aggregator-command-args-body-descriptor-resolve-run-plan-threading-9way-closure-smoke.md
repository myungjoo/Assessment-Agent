# T-0778 — realdata-e2e step④ aggregator command-args-body 합류 9-way single-source closure non-gated build-time smoke 신설

## Why

PLAN.md §109(🟢 실 평가 e2e, P5)의 step④ 멱등 search-or-update 의 build-time 순수 layer 는 **검증된 단일 run plan(`buildRealDataE2eRunPlan(seeds, modelId, run)` → `{pipeline, run}`, T-0597)을 pre-실행 aggregator(`buildRealDataE2eStepArgs(runPlan, activities, results)` → `{evaluation, publish}`, T-0601)에 통째로 넘긴다**. 이 aggregator 는 세 입력 source(`runPlan`·`activities`·`results`)를 받고, T-0777 이 publish leg 의 사람-대면 렌더 산물 `report.descriptor.body` 를 단일 source `(results, runPlan.run)` 재유도 byte-identical 로 closure 에 묶어 8-way 를 완성했다.

직전 sweep 은 aggregator publish leg 의 **report.descriptor.body(사람-대면 이슈 본문 렌더)** 와 **report.summary(정량 집계 객체)** 를 단일 source 재유도로 묶었으나, publish leg 의 `commandArgs` 측에는 아직 closure 에 미합류된 distinct 한 실행-인자 surface 가 있다 — **`commandArgs.createArgs.body`(gh issue create 경로 이슈 본문)** 와 **`commandArgs.updateArgs.body`(gh issue edit 경로 이슈 본문)**.

`commandArgs.{createArgs,updateArgs}.body` 축은 `report.descriptor.body`(T-0777) 와 distinct 한 표면이다:

- **command-args-body 축(본 task 의 새 표면)** — `stepArgs.publish.commandArgs.createArgs.body: string` 과 `stepArgs.publish.commandArgs.updateArgs.body: string`(`buildRealDataResultIssueCommandArgs(descriptor)`, T-0583 이 create/update 두 경로 모두에 `descriptor.body` 를 그대로 전달 — `realdata-e2e-result-issue-command-args.ts` 130~138행)는 **동일 aggregator 산출 `stepArgs.publish.report.descriptor.body` 와 byte-identical**. 즉 live runner 가 실제로 `gh issue create --body <X>` 또는 `gh issue edit --body <X>` 로 거는 **두 실행 경로의 이슈 본문 필드**가 모두 같은 단일-source 렌더 본문을 운반한다. `report.descriptor.body`(T-0777 이 묶은, report 측 사람-대면 렌더)는 **로깅·검증·이슈 본문 source** 이지만, `commandArgs.{create,update}Args.body` 는 **실 gh 명령 인자로 나가는 실행 surface** — create 든 update 든 어느 멱등 분기로 박제하든 marker 라인 보존(멱등 검색 토큰)을 위해 같은 body 가 두 경로에 들어가야 함이 search-or-update 멱등성의 핵심이다(REQ-009). 이 "두 실행 경로 body == report descriptor.body == 단일-source 렌더" 정합은 미합류.

직전 sibling 들은 이 command-args-body 축을 aggregator+resolve+post closure 에 합류시키지 않았다:
- **T-0777 (aggregator 8-way)**: publish leg 의 `report.descriptor.body`(=results+run 재유도)+`report.summary`+evaluation inputs/modelId+marker/searchArgv/run-identity 를 단일 (runPlan, activities, results) source 로 수렴 박제. 그러나 **`commandArgs.createArgs.body`·`commandArgs.updateArgs.body`(=descriptor.body 가 실 gh 명령 인자로 들어간 두 실행 경로 surface)는 closure 에 미합류** — descriptor.body(report 측)만 묶음.
- **T-0776/0775/0774/0773 (aggregator 7·6·5·4-way)**: commandArgs 는 `searchQuery` 축(marker)만 합류 — `createArgs.body`·`updateArgs.body` 미합류.
- **command-args / command-args-body-marker / command-plan helper·assembly smoke**: createArgs.body/updateArgs.body 의 marker-first 보존·descriptor.body 전달 자체는 박제했으나 **aggregator(`buildRealDataE2eStepArgs`) 진입·resolve·post 미합류**(단독 helper 호출 또는 command-plan-level assembly 만 — gap 확인 6 smoke 전부 aggregator=N·post=N).

본 task 는 그 빈 자리를 채워 **publish leg 의 두 실행 경로 body(createArgs.body·updateArgs.body)를 같은 aggregator 산출 descriptor.body 와 byte-identical 로 closure 에 묶어**, 검증 source `(runPlan, activities, results)` 세 source 가 aggregator publish leg 의 세 출력 surface(정량 집계 summary + 사람-대면 렌더 descriptor.body + 실행-인자 command-args body 두 경로)와 evaluation leg(inputs+modelId), 그리고 marker/searchArgv/run-identity 의 source 임을 resolve+post 까지 묶은 한 chain 으로 박제한다. 단일 source `(runPlan, activities, results, search-stdout, exec-stdout)` 로부터:

1. **publish-leg command-args-body 두 경로 일치(축 9, 본 task 의 새 표면)** — `stepArgs = buildRealDataE2eStepArgs(runPlan, activities, results)` → `stepArgs.publish.commandArgs.createArgs.body` 와 `stepArgs.publish.commandArgs.updateArgs.body` 가 **둘 다 `stepArgs.publish.report.descriptor.body` 와 byte-identical string equal**. 즉 gh issue create 경로 본문 == gh issue edit 경로 본문 == report descriptor 본문 == 단일-source 렌더. create/update 어느 멱등 분기든 같은 본문이 나감(marker 라인 보존 → 멱등 검색 가능).
2. **publish-leg descriptor-body 렌더 재유도(축 8, T-0777 cover 영역의 9-way 묶음 항)** — `stepArgs.publish.report.descriptor.body` 가 동일 `results`·동일 `runPlan.run` 으로 직접 호출한 `buildRealDataResultIssueCommandPlan(results, runPlan.run).report.descriptor.body` 와 byte-identical string equal.
3. **publish-leg results-summary 재유도(축 7)** — `stepArgs.publish.report.summary` 가 `buildRealDataResultIssueCommandPlan(results, runPlan.run).report.summary` 와 byte-identical deep-equal.
4. **evaluation-leg inputs 재유도 + 페어링(축 6)** — `stepArgs.evaluation.inputs` 가 `buildRealDataEvaluationInputs(activities)` 와 byte-identical, `callArgs[i].input === inputs[i]`.
5. **evaluation-leg modelId thread(축 5)** — 모든 `callArgs[i].options.modelId === runPlan.pipeline.modelId`.
6. **publish-leg 내부 marker 3-축 일치(축 2~4)** — `descriptor.marker === commandArgs.searchQuery === extractSearchMarker(searchArgv)`.
7. **resolve issueNumber + post run-identity(축 1, 종단)** — `resolvePlan = resolveRealDataResultIssueGhCommandPlan(searchStdout, stepArgs.publish.commandArgs)` → `action.update.issueNumber = N` → `outcomeReport = buildRealDataResultOutcomeStepArgs(runPlan, execStdout)` → `{issueNumber, gitSha, dateToken, ...}` 가 동일 runPlan.run 전파.

이 9-way(command-args body 두 경로 일치 + descriptor.body 재유도 + summary 재유도 + inputs 재유도 + modelId + marker 3-축 + resolve issueNumber + post run-identity)가 **세 검증 source `(runPlan, activities, results)`** single-source 로 수렴함이 **search-or-update 멱등성**(REQ-009 — create/update 두 경로가 같은 marker-보존 본문)·**raw 미보유 평가 입력/결과 집계 정합**(REQ-032)·**결과 리포트 재실행 정합**(REQ-037)의 aggregator-level "정량 집계(summary)+사람-대면 본문(descriptor.body)+실행 인자 본문(create/update body)+평가 입력(inputs)+평가 정책(modelId)+publish 식별(marker/searchArgv/run-identity)이 같은 세 검증 source 에서 나옴" 의 종단 닫음이다. **publish leg 의 세 출력 surface(summary 객체 + descriptor.body 렌더 + command-args 두 실행 경로 body)가 모두 단일-source 재유도/일치로 묶이는 slice** 다.

gap 확인(git grep, origin/main 9b365124): `for f in test/smoke/realdata-e2e*.smoke-spec.ts; do (buildRealDataE2eStepArgs AND (createArgs.body OR updateArgs.body) 동시-참조) 여부; done` — **0 파일**(직전 fire 실측 확인 — createArgs.body/updateArgs.body 참조 6 smoke 전부 aggregator=N·post=N, command-plan/command-args helper-level assembly 만; T-0777 8-way 는 report.descriptor.body 만 합류·command-args body 필드 미합류). `git log origin/main` 동일 영역 박제 commit 0.

live leg(실 prisma·실 collectForPerson·실 github.com fetch·실 LLM scoring·실 gh CLI 실행·DB·LAN gate) 복제 0·non-gated 항상 실행 — 순수 build-time in-memory 검증만.
