# T-1085 — result-issue-descriptor-body 구조-검사 선행성 order-lock (clean leg — 신규 namespace import + spyOn 인프라)

## Why

P5 test-hardening 의 realdata-e2e 구조-guard 선행성 sweep(T-1065 §D 후보 (a))은 leg 1 result-report-plan(T-1066) → … → leg 17 evaluation-step-args(T-1082) → leg 18 result-publish-step-args(T-1083) → leg 19 result-outcome-step-args(T-1084)로 step-args family 4종을 소진했다. T-1084 Follow-up 이 지목한 대로 **broader realdata-e2e producer/aggregator layer 중 spyOn 부재·구조 error-path 0-call 결손분**으로 전환해, **result-issue-descriptor-body consistency 가드**(`test/helpers/realdata-e2e-result-issue-descriptor-body-consistency.ts`)를 leg 20 으로 삼는다. 이 가드 `assertRealDataResultIssueDescriptorBodyConsistent`(L131~)는 실 평가 e2e 결과 이슈 descriptor 의 `body` 3 블록 구조(marker / "" / 한 줄 요약 / "" / markdown 본문)를 single source `summary` 로 위임 재유도(`formatRealDataResultSummaryLine(summary)` L142 + `renderRealDataResultSummaryMarkdown(summary)` L143)해 byte-identical 대조하는 post-composition 무결성 가드다(README.md 109행 step ④ 결과 박제 chain 의 body 합성 무결성 / REQ-032·REQ-059). 앞선 result-* leg 와 동형이나 재유도 delegate 가 **2개**(한 줄 요약 formatter + markdown renderer), 상위 구조 assert 는 **2개**(descriptor / summary top-level)다.

**clean-leg 성격(variant 아님)**: T-1084 leg 는 spec 이 delegate 를 이미 namespace import + happy-path spyOn 하고 있어 기존 인프라 재사용 variant 였다. 반면 본 leg 의 spec(총 451줄)은 delegate 2개를 **value named import**(L46 `import { formatRealDataResultSummaryLine } from "./realdata-e2e-result-summary-line"`, L47 `import { renderRealDataResultSummaryMarkdown } from "./realdata-e2e-result-summary-markdown"`)로만 가져와 expected-value 계산에 쓰고, `import * as` namespace import 도 `jest.spyOn` 도 `toHaveBeenCalled*` 도 전무하다(pre-check grep: `toHaveBeenCalledTimes(0)` = 0, `jest.spyOn` = 0). 따라서 본 leg 는 T-1082/T-1083 와 같은 **clean-leg** — delegate 2개 각각의 **신규 namespace import 신설 + spyOn 인프라 신설**이 필요하다.

planner pre-check(실 grep + read, 2026-07-18, HEAD 6c55a4f9 = T-1084 머지 포함)로 확인한 gap: 이 가드는 본문에서 **2 상위 구조 assert**(`assertDescriptorStructure(descriptor)` L136 — descriptor null/undefined·`body` 비-string·`marker` 비-string → TypeError; `assertSummaryStructure(summary)` L137 — summary null/undefined → TypeError)를 **body 재유도 위임 2개**(`formatRealDataResultSummaryLine(summary)` L142 / `renderRealDataResultSummaryMarkdown(summary)` L143)보다 **먼저** 수행한다(구조검사 L136~137 < 재유도 L142~143). 구조 검사와 재유도 **사이에 RangeError 분기가 없다** — 값 정합 위반 RangeError(불변식 1~6, L145 이후)는 전부 재유도 **뒤**에 온다. 그러나 대응 spec 의 상위 구조 error-path `it` 6건(`descriptor null → TypeError` L140 / `summary null → TypeError` L158 / `descriptor undefined → TypeError` L176 / `summary undefined → TypeError` L188 / `descriptor.body 비-string → TypeError` L200 / `descriptor.marker 비-string → TypeError` L216)은 `.toThrow(TypeError)` 만 assert 하고 delegate 호출 횟수를 못박지 않는다. 즉 **상위 구조 결손 입력을 주면 body 재유도 delegate 2개가 `toHaveBeenCalledTimes(0)` 이어야 한다는 선행성**이 spy 로 못박혀 있지 않다. 이를 상위 구조 결손 6 분기(descriptor null·undefined·body 비-string·marker 비-string·summary null·undefined)에 delegate `formatRealDataResultSummaryLine` / `renderRealDataResultSummaryMarkdown` 각각 `toHaveBeenCalledTimes(0)` 으로 못박아 "상위 구조 검사 → body 재유도" 순서를 silent 재정렬로부터 방어한다(T-1066~T-1084 와 동형 defense-in-depth, delegate 2개). test-only 1파일, production `src`·helper `.ts` 로직 무변경.

**0-call 범위 경계(중요)**: 가드 주석(L139~141)이 명시하듯 재유도 delegate 2개는 호출 시점에 summary 의 **심층 필드**(byDifficulty·byContribution) 를 self-guard 로 추가 검증한다. 따라서 심층 필드 결손은 delegate 가 **호출된 뒤** TypeError 전파로 catch 되므로(delegate 1-call), 본 leg 의 0-call 선행성은 **상위 구조 guard 2개가 잡는 top-level 결손**(descriptor null/undefined·body 비-string·marker 비-string·summary null/undefined 6 분기)에만 적용한다. summary 심층 필드 결손(byDifficulty/byContribution 누락)에 대한 0-call assert 는 **본 leg 범위 밖**(delegate 가 그 검증 주체라 0-call 이 아님) — Out of Scope 에 명시.
