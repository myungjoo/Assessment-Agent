# T-0797 — redeploy 오케스트레이션-진입점 계약 ↔ 실 배포 artifact(redeploy.sh · seed-llm-config.sh · docker-compose.yml · systemd unit) parity drift-detection non-gated build-time smoke 신설

## Why

`deploy/redeploy.sh` 는 본 시스템의 **무인 야간 재배포 체인의 진입점 오케스트레이터**다 — systemd `.timer`(매일 03:00) → `.service`(oneshot) → `redeploy.sh`(origin/main 동기 → 이미지 재빌드 → 컨테이너 무중단 교체 → LLM config seed → 잔여 이미지 정리) 가 하나의 무인 배포 routine 을 구성한다. 이 체인은 **여러 artifact 사이의 경로/식별자 계약** 위에서만 작동한다(origin/main `7a7a5641` 실측):

1. **systemd `.service` ExecStart ↔ 실 redeploy.sh 파일 실존** — `assessment-agent-redeploy.service` 의 `ExecStart=/opt/assessment-agent/deploy/redeploy.sh` 의 경로 suffix(`deploy/redeploy.sh`)는 실 `deploy/redeploy.sh` 파일을 가리켜야 한다. redeploy.sh 가 이동/rename 되면서 service 를 미동기하면 — systemd 가 `ExecStart` 에서 "No such file or directory" 로 oneshot 실패(야간 재배포 통째로 안 됨), 그런데 그건 03:00 에 실 호스트에서 처음 터지기 전까지 검출 0.
2. **systemd `.service` 경로 식별자 triple-match** — `.service` 는 `ExecStart=/opt/assessment-agent/deploy/redeploy.sh`·`Environment=REPO_DIR=/opt/assessment-agent`·`WorkingDirectory=/opt/assessment-agent` 세 곳에서 동일 배포 루트 `/opt/assessment-agent` 를 전제한다. 이 셋이 silent 하게 어긋나면(예: WorkingDirectory 만 바뀜) redeploy.sh 가 `cd "$REPO_DIR"` 후 엉뚱한 디렉토리에서 동작하거나 git/docker 명령이 잘못된 트리에서 실행된다.
3. **redeploy.sh `REPO_DIR` 기본값 ↔ systemd `Environment=REPO_DIR`** — redeploy.sh 는 `REPO_DIR="${REPO_DIR:-/opt/assessment-agent}"` 로 기본값을 박제하고, systemd `.service` 는 `Environment=REPO_DIR=/opt/assessment-agent` 로 주입한다. 두 곳의 `/opt/assessment-agent` 가 어긋나면 — service 경유 실행(주입값)과 cron/수동 실행(기본값)이 서로 다른 배포 루트를 쓰게 되어 배포 위치가 갈린다.
4. **redeploy.sh 의 `bash $REPO_DIR/deploy/seed-llm-config.sh` 호출 경로 ↔ 실 seed-llm-config.sh 파일 실존** — redeploy.sh 는 재배포 직후 `if [ -f "$REPO_DIR/deploy/seed-llm-config.sh" ]; then ... bash "$REPO_DIR/deploy/seed-llm-config.sh"` 로 LLM provider config 를 멱등 seed 한다. 그 호출 경로 suffix(`deploy/seed-llm-config.sh`)는 실 `deploy/seed-llm-config.sh` 파일을 가리켜야 한다. seed 스크립트가 이동/rename 되면서 redeploy.sh 를 미동기하면 — `[ -f ... ]` guard 가 false 가 되어 LLM config seed 가 silent 하게 skip(환경 고유 LLM endpoint 미주입, 그러나 재배포는 계속되어 검출 안 됨).
5. **redeploy.sh 의 `docker compose up -d --build` ↔ docker-compose.yml 실존** — redeploy.sh 는 `docker compose up -d --build` 한 번으로 이미지 재빌드 + 컨테이너 교체를 한다. 이건 `docker-compose.yml`(또는 compose 파일)이 repo-root 에 실존함을 전제한다. compose 파일이 이동/삭제되면 docker compose 가 "no configuration file" 로 실패해 재배포 전체가 깨진다.

만약 누군가 silent 하게 (a) redeploy.sh 를 이동/rename 하면서 systemd `.service` ExecStart 를 미동기하거나, (b) `.service` 의 ExecStart/REPO_DIR/WorkingDirectory 중 하나만 배포 루트를 바꾸거나, (c) redeploy.sh `REPO_DIR` 기본값과 `.service` `Environment=REPO_DIR` 를 어긋나게 두거나, (d) seed-llm-config.sh 를 이동하면서 redeploy.sh 의 호출 경로를 미동기하거나, (e) docker-compose.yml 을 옮기면 — 그 시점부터 무인 야간 재배포(systemd timer 03:00)가 silent 하게 실패하거나(host 에서 처음 터질 때까지 검출 0) LLM config seed layer 가 누락된다. build-time parity smoke 가 이를 push 전(또는 같은 PR 의 smoke 단계)에서 정적으로 잡는다(REQ-061 smoke-in-CI, REQ-062 build artifact 정합).

직전 sweep 들은 `deploy/` 의 build-time seam 6종 + CI 검증-체인 1종을 차례로 닫았다 — daily-test.sh `step_eval` argv(T-0790)·머신-JSON 스키마(T-0791)·HTTP step↔route(T-0792)·docker-entrypoint↔build artifact(T-0793)·seed-llm-config SQL/cipher↔schema(T-0794)·docker-compose 오케스트레이션↔artifact(T-0795)·ci.yml 검증-체인↔scripts(T-0796). **T-0796 Follow-up 은 잔여 후보 (d1)`web/package.json` 워크스페이스 script 정합·(d2)`deploy/README.md` 설치 절차 명령 정합을 HIGH bar 엄격 재판정하라고 지시**했다. 본 task 는 그 둘을 보류하고(아래 판정), 아직 닫히지 않은 **distinct genuine seam = redeploy 오케스트레이션-진입점 계약** 을 채택한다.
