# T-0796 — CI workflow 검증-체인 계약 ↔ 실 build/test artifact(package.json scripts · 스크립트 파일 · jest config) parity drift-detection non-gated build-time smoke 신설

## Why

`.github/workflows/ci.yml` 은 본 시스템의 **R-110/R-111/R-113 검증 체인(코드 검토 + test 작성 + test 수행 + smoke + e2e 가 CI 에서 자동 실행)** 을 실제로 구성하는 단일 진입점이다. CLAUDE.md §3.2 가 "test fail → CI error" 를 우회 불가 절대 규칙으로 강제하는데, 그 강제는 ci.yml 이 호출하는 인보케이션 토큰이 실 build/test artifact 와 정합할 때만 유효하다. ci.yml 은 다수의 `run: pnpm <script>` 와 `run: bash <path>` 를 통해 검증 체인을 조립한다(origin/main 실측):

1. **`run: pnpm <script>` 인보케이션 ↔ package.json scripts 실존** — ci.yml 은 `pnpm lint`(153행)·`pnpm build`(156행)·`pnpm test:cov`(180행)·`pnpm test:smoke`(185행)·`pnpm test:e2e`(191행) 등 루트 워크스페이스 script 를 호출한다. 이 `<script>` 토큰들은 전부 `package.json` 의 `scripts` 객체에 키로 존재해야 한다. 누군가 package.json 에서 `test:smoke` 를 `test:smoke:all` 로 rename 하거나 `test:cov` 를 지우면서 ci.yml 을 미동기하면 — CI step 이 `pnpm test:smoke` 호출 시 pnpm 이 "script not found" 로 error 하거나(R-113 smoke layer 가 CI 에서 실행 안 됨) 더 나쁘게는 silent 하게 검증 layer 가 누락된다.
2. **`run: bash <path>` 인보케이션 ↔ 실 스크립트 파일 실존** — ci.yml 은 `bash scripts/check-spec-presence.test.sh`(87행)·`bash scripts/check-doc-only-pr.test.sh`(92행)·`bash scripts/verify-ref-cas-lock.sh`(97행)·`bash scripts/select-claim.test.sh`(104행)·`bash scripts/reclaim-stale-claim.test.sh`(112행)·`bash scripts/acquire-lock.test.sh`(119행)·`bash scripts/lib-lock-tree.test.sh`(128행)·`bash deploy/daily-test-step-eval.test.sh`(136행) 등 shell 검증 스크립트를 직접 호출한다. 이 `<path>` 들은 전부 실 파일로 실존해야 한다. 스크립트 파일이 이동/rename/삭제되면서 ci.yml 을 미동기하면 — CI step 이 `bash <path>` 에서 "No such file" 로 error(CI red) 또는 검증 layer 누락.
3. **package.json `test:smoke`/`test:e2e` 가 가리키는 jest config 파일 실존** — `package.json` 의 `test:smoke` = `jest --config ./test/jest-smoke.json`, `test:e2e` = `jest --config ./test/jest-e2e.json`. ci.yml 이 호출하는 `pnpm test:smoke`/`pnpm test:e2e` 가 실제로 발화하려면 그 `--config <path>` 가 가리키는 jest config 파일(`test/jest-smoke.json`·`test/jest-e2e.json`)이 실존해야 한다. config 파일이 이동/삭제되면 smoke/e2e layer 가 통째로 실행 불가.
4. **검증 layer 완결성(R-110/111/113 체인이 빠짐없이 존재)** — ci.yml 이 R-113 의 unit+smoke+e2e 3종을 모두 발화하려면 `pnpm test:cov`(unit+coverage)·`pnpm test:smoke`(smoke)·`pnpm test:e2e`(e2e) 인보케이션이 ci.yml 에 모두 존재해야 한다. 셋 중 하나가 silent 하게 ci.yml 에서 빠지면 그 test layer 가 CI 에서 실행되지 않아 R-113 위반이 검출되지 않는다.

만약 누군가 silent 하게 (a) package.json 에서 ci.yml 이 호출하는 script 를 rename/삭제하거나, (b) ci.yml 이 `bash <path>` 로 호출하는 스크립트 파일을 이동/삭제하거나, (c) test:smoke/test:e2e 가 가리키는 jest config 파일을 옮기거나, (d) ci.yml 에서 핵심 test layer 인보케이션(test:cov/test:smoke/test:e2e) 중 하나를 빠뜨리면 — 그 시점부터 CI 가 silent error 하거나 검증 layer 가 누락되어 R-110/R-111/R-113 절대 규칙이 무력화된다. 이는 무인 자동화의 핵심 안전망(test fail → CI error → merge 차단)을 깨뜨린다(REQ-061 smoke-in-CI, REQ-062 build artifact 정합).

직전 sweep 들은 `deploy/` 의 build-time seam 6종을 차례로 닫았다 — daily-test.sh `step_eval` argv(T-0790)·머신-JSON 스키마(T-0791)·HTTP step↔route(T-0792)·docker-entrypoint↔build artifact(T-0793)·seed-llm-config SQL/cipher↔schema(T-0794)·docker-compose 오케스트레이션↔artifact(T-0795). **T-0795 Follow-up 은 deploy build-time cross-artifact seam 이 "사실상 소진" 됐다고 명시하고, 잔여 후보 (c1)`deploy/assessment-agent-redeploy.{service,timer}` systemd unit ExecStart↔redeploy.sh 정합은 "unit 파일 1~2 토큰뿐이라 seam 빈약 위험" 이라 HIGH bar 엄격 재판정을 지시**했다. 본 task 는 그 (c1) 후보를 HIGH bar 로 재판정해 **거부**한다 — systemd unit 은 `ExecStart=/opt/.../deploy/redeploy.sh` 1줄·`WorkingDirectory` 1줄·`OnCalendar` 1줄뿐으로 cross-artifact parity 토큰이 빈약(rephrase 양산 위험)하다. 대신 T-0795 Follow-up 이 정직한 escalate 대안으로 허용한 **distinct genuine seam** 으로 전환한다.
