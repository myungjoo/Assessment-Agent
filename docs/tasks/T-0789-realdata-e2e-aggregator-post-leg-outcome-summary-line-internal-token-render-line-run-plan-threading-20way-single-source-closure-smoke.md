# T-0789 — realdata-e2e step④ aggregator post-leg outcomeReport.summaryLine internal-token render-line per-token 1:1 thread 합류 20-way single-source closure non-gated build-time smoke 신설

## Why

PLAN.md §109(🟢 실 평가 e2e, P5)의 build-time 순수 layer 는 최외곽 단일 진입 `buildRealDataE2eRunPlan(seeds, modelId, run)` → `{pipeline, run}`(T-0597)을 산출하고, pre-실행 aggregator `buildRealDataE2eStepArgs(runPlan, activities, results)` → `{evaluation, publish}`(T-0601)에 통째로 넘긴 뒤, **post-실행** 측은 `buildRealDataResultOutcomeStepArgs(runPlan, execStdout)`(T-0600) → `RealDataResultIssueOutcomeReport {issueNumber, url, gitSha, dateToken, summaryLine}`(T-0590) 으로 닫는다. 직전 sweep(T-0778~0788)은 aggregator 세 leg 표면 + 세 leg 내부-shape(collect serviceIdentities T-0785·evaluate input T-0786·publish summary T-0787) + publish-leg descriptor.body render-line 깊이(T-0788)를 단일 source 로 묶어 19-way 를 완성했다.

T-0788 Follow-up (a)는 다음 sweep 후보로 **post-leg outcomeReport.summaryLine 의 results→요약 라인 원소별 집계 정합**을 HIGH bar 재판정 대상으로 남겼다. 본 task 의 사전 조사(origin/main 9b780fcc) 결과:

- post-leg `summaryLine` 의 production 합성식은 `` `[${run.dateToken}@${run.gitSha}] 결과 이슈 #${outcome.issueNumber} 박제 → ${url}` ``(realdata-e2e-result-issue-outcome-report.ts 119행) 이다 — **results→슬롯 집계(count·byDifficulty·byContribution·totalVolume)를 일절 운반하지 않는다**. 따라서 Follow-up (a)의 "results→summary-line per-slot 집계" 가설은 **거짓**(descriptor.body 의 한 줄 요약 `formatRealDataResultSummaryLine` 와 달리 post-leg summaryLine 은 run-identity + issueNumber + url 토큰만 보유). 이 점에서 results 집계 합류는 distinct seam 이 아니다.
- 그러나 **다른 genuine distinct seam 이 존재한다**: 기존 aggregator sweep 17 smoke 는 `outcomeReport.summaryLine` 을 오직 `.length > 0`(non-empty) + `.toContain(runPlan.run.gitSha)` + `.toContain(runPlan.run.dateToken)` **substring-contains** 로만 단언한다(14-way 597·598행 등 전 sibling 동형). **summaryLine 의 토큰-위치별 1:1 render-line 재유도**(전체 문자열이 `[dateToken@gitSha] 결과 이슈 #N 박제 → url` byte-identical, 각 토큰 슬롯 — `dateToken@gitSha` 묶음 == `runPlan.run`, `#N` == `resolvePlan.action.issueNumber` == `execStdout` URL 의 `/issues/N`, 종단 `url` 토큰 == parse 산출 url — 이 source 슬롯과 정확히 1:1)와 **production `buildRealDataResultIssueOutcomeReportFromOutput(execStdout, runPlan.run).summaryLine` 와의 byte-identical** 단언은 0이다.

이 **post-leg summaryLine internal-token render-line 내부-shape 깊이**는 publish-leg 의 descriptor.body render-line 깊이(T-0788, summary 슬롯→markdown body 라인 1:1)의 **post-leg 대칭** 이다 — RealDataResultIssueOutcomeReport(객체)가 사람이 로그/이슈 코멘트로 읽을 한 줄 확인 문자열 토큰으로 어떻게 render 되는가(토큰-위치 1:1) 의 깊이. 19-way 가 잡은 19축과 distinct 한 표면이다:

- **post-leg outcomeReport.summaryLine internal-token render-line per-token 1:1 thread 축(본 task 의 새 표면)** — aggregator+resolve+post chain(`buildRealDataResultOutcomeStepArgs(runPlan, execStdout)`)이 산출한 `outcomeReport.summaryLine` 이:
  - `buildRealDataResultIssueOutcomeReportFromOutput(execStdout, runPlan.run).summaryLine`(production post-leg 위임 직접 호출) 산출과 **byte-identical**(`toBe`) — post step-args 컴포저가 위임 layer 사이에서 summaryLine 을 변형/누락하지 0.
  - **토큰-위치별 1:1 재유도**: spec-로컬 독립 재조립(production summaryLine helper 호출 0, source 슬롯을 spec 로컬 template `` `[${dt}@${sha}] 결과 이슈 #${n} 박제 → ${url}` `` 로 직접 조립)과 byte-identical, AND `summaryLine` 이 `runPlan.run.dateToken`·`runPlan.run.gitSha`·`String(resolvePlan.action.issueNumber)`·`outcomeReport.url` 각 토큰을 정확한 위치(접두 `[`·구분 `@`·`] 결과 이슈 #`·` 박제 → ` 리터럴 사이)에 포함(`toContain` + 위치 인덱스 단조).
  - **issueNumber 토큰 cross-leg 1:1**: summaryLine 의 `#N` 의 N === `outcomeReport.issueNumber` === `resolvePlan.action.issueNumber`(resolve leg) === `execStdout` URL 의 `/issues/N` 의 N(검증 source N) — 단일 number 가 resolve+post+summaryLine render 토큰까지 1:1.
  - **raw-not-stored boundary**(REQ-059) — summaryLine 이 run-identity + issueNumber + url 토큰만 보유, results narrative·byDifficulty/byContribution 슬롯값·raw 활동 본문·credential 어휘 미surface(EvaluationResult.narrative 가 summaryLine 으로 새지 않음).
  - 이 1:1 이 aggregator 가 thread 하는 **그 동일 `runPlan.run`** 에서 나온다(`outcomeReport.{gitSha,dateToken}` 가 `runPlan.run` 과 같은 single-source, 19-way 묶음 항).

직전 sibling 들은 이 summaryLine internal-token render-line 축을 closure 에 합류시키지 않았다:
- **T-0788 (aggregator 19-way)**: publish-leg descriptor.body render-line(summary 슬롯→body 라인 1:1) + 18축. outcomeReport 는 `issueNumber.toBe(N)`·`{gitSha,dateToken}.toBe(runPlan.run)`·summaryLine credential-free 만(513~515·1058~1059·1235~1236·1541~1542행) — **summaryLine 토큰-위치 1:1 render-line·production byte-identical 미합류**.
- **T-0778~0787 (aggregator 9~18-way)**: summaryLine 을 substring-contains(.toContain gitSha/dateToken) 또는 typeof/length sanity 만 — 토큰-위치 1:1 깊이 0.
- **outcome-report / from-output / summary-line-consistency helper spec**: `buildRealDataResultIssueOutcomeReport`(T-0590) + `buildRealDataResultIssueOutcomeReportFromOutput`(T-0596) + `assertRealDataResultIssueOutcomeReportSummaryLineConsistent`(T-0701) self-guard·spec 가 summaryLine 합성·토큰 정합을 박제했으나 **aggregator(`buildRealDataResultOutcomeStepArgs`/`buildRealDataE2eStepArgs`) chain 진입·resolve·publish-leg 미합류**(post-leg 위임 helper 단독 spec — aggregator+resolve 종단 closure 와 summaryLine 토큰 1:1 정합 0).

본 task 는 그 빈 자리를 채워 **post step-args 컴포저가 산출한 outcomeReport.summaryLine(한 줄 확인 문자열)이 그 source `(runPlan.run, resolvePlan issueNumber N, execStdout url)` 로부터 production byte-identical·토큰-위치별 1:1 render 임을, publish-leg descriptor.body render-line·summary 내부-shape·evaluation-leg·collect-leg·command-args·resolve·marker 와 묶어 closure 에 합류**시킨다. 단일 source `(seeds, modelId, run, activities, results, search-stdout, exec-stdout)` 로부터:

1. **post-leg summaryLine internal-token render-line per-token 1:1 thread(축 20, 본 task 의 새 표면)** — `outcomeReport = buildRealDataResultOutcomeStepArgs(runPlan, execStdout)` → `outcomeReport.summaryLine` 이 `buildRealDataResultIssueOutcomeReportFromOutput(execStdout, runPlan.run).summaryLine`(production 위임 직접 호출) 와 byte-identical, AND spec-로컬 독립 재조립과 byte-identical, AND 토큰 `#N`==resolve issueNumber==url /issues/N, `dateToken@gitSha`==runPlan.run.
2. **publish-leg descriptor.body render-line per-slot 1:1(축 19, 19-way 묶음 항)** — `stepArgs.publish.report.descriptor.body` 가 그 leg summary 로부터 `renderRealDataResultSummaryMarkdown` + `formatRealDataResultSummaryLine` byte-identical·난이도 표 3행·기여도 표 4행 슬롯별 1:1(전 enum 슬롯 라인 존재/미등장 0).
3. **publish-leg summary 내부-shape per-result 1:1 집계 + summary/descriptor top-level 재유도(묶음 항)** — `stepArgs.publish.report.summary == buildRealDataResultSummary(results)` 원소별 1:1, `descriptor.body`/`summary` byte-identical `buildRealDataResultIssueCommandPlan(results, runPlan.run).report.*`.
4. **evaluation-leg input 내부-shape 1:1(묶음 항)** — `stepArgs.evaluation.inputs[i] == mapActivityToEvaluationInput(activities[i])` 필드별 byte-identical.
5. **collect-leg serviceIdentities 내부-shape + collectCallArgs top-level 재유도(묶음 항)** — `collectCallArgs[i].person.serviceIdentities` 가 `seeds[i] {service,externalId}` 추림과 1:1, `collectCallArgs == buildRealDataCollectCallArgs(seeds)`.
6. **inputs top-level 재유도 + callArgs.input 페어링(묶음 항)** — `inputs == buildRealDataEvaluationInputs(activities)`, `callArgs[i].input === inputs[i]`.
7. **search-json-fields↔parse-shape set-equal + number→resolve→post thread(묶음 항)** — `searchArgv[6]` split 집합 == `PARSE_SHAPE_KEYS` == 실 파싱 hit 키 set-equal, N → resolve → post → summaryLine `#N`.
8. **collect/evaluate modelId 공유(묶음 항)** — `runPlan.pipeline.modelId === modelId === callArgs[i].options.modelId`.
9. **search-argv 전체-벡터 + resolve-argv create/update + command-args labels/title/body + descriptor + marker 3-축 + resolve issueNumber + post run-identity(종단)**.

이 20-way(post-leg summaryLine internal-token render-line per-token 1:1 + publish-leg descriptor.body render-line + summary 내부-shape per-result 집계 + summary/descriptor top-level 재유도 + evaluation-leg input 내부-shape + collect-leg serviceIdentities 내부-shape + collectCallArgs top-level 재유도 + inputs top-level + callArgs.input 페어링 + collect/evaluate modelId 공유 + search-json-fields↔parse-shape set-equal + number thread + search-argv 전체-벡터 + resolve-argv create/update + command-args labels + title/body 두 경로 + descriptor 재유도 + marker 3-축 + resolve issueNumber + post run-identity)가 **검증 source `(seeds, modelId, run, activities, results, exec-stdout)`** single-source 로 수렴함이 **search-or-update 멱등성**(REQ-009)·**raw 미보유 평가 결과 정합**(REQ-032)·**정성 분류 집계 정합**(REQ-038)·**raw 미저장**(REQ-059)의 aggregator-level "e2e 의 post-leg 가 박제 결과를 사람이 읽을 한 줄 확인 문자열로 render 하는 token 깊이까지 단일 검증 source(run-identity·issueNumber·url)에서 토큰-위치별 어긋남 0, narrative raw 는 confirmation 라인으로 새지 않음" 의 종단 닫음이다. **e2e 의 post-leg render-line 깊이가 publish-leg descriptor.body render-line(19-way)의 대칭으로 closure 에 합류하는 seam slice** 다(세 leg 내부-shape + publish-leg 표현-layer 렌더 깊이에 이어 post-leg 표현-layer 렌더 깊이 추가 — render-line 내부-shape closure 완성).

(outcome-report / from-output / summary-line-consistency helper spec 은 post-leg 위임 helper 단독 — aggregator+resolve chain 진입·publish-leg 종단 미합류.)
