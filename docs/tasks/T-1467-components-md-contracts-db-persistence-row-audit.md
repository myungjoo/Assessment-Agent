# T-1467 — components.md `## Contracts` `DB Persistence → PostgreSQL` row 대조

## Why

[T-1466](T-1466-components-md-contracts-worker-rows-audit.md) 가 `## Contracts` 표의 **Worker 발신 4 row (280 ~ 283 행)** 를 닫으면서 ([REQ-COVERAGE-AUDIT.md](../use-cases/REQ-COVERAGE-AUDIT.md) `§ 12.64`) 파생 영향 **(1)** 에서 **잔여 4 row (`DB Persistence → PostgreSQL` 1 + 외부 egress 3)** 를 다음 slice 1 순위로 지목했다. 본 slice 는 그 지목을 승계하되, `§ 12.64` FU (1) 이 스스로 단 단서 — **"egress 3 row 는 fan-out 축약 6 (edge 9 : row 3) 이 몰려 있어 축 수가 늘어나므로 축 상한 초과가 보이면 284 단독 + egress 3 으로 2 slice 분할한다"** — 를 planner 가 **분할 쪽으로 판단** 해 **284 행 1 row 만** 다룬다. 근거: egress 3 row 는 row 당 claim 이 (결선 · protocol · auth · ADR pointer · 4xx 이벤트 · 미래 시제) **5 ~ 6** 개라 4 row 통합 시 축이 **12 이상** 으로 늘고 audit 절 **≤ 100 행** 상한 (`§ 12.61` 이후 전 slice 가 지킨 규약) 을 넘길 것이 예상되기 때문이다. **분할 판단의 근거 수치는 AC 3 에서 실측으로 재확인** 한다.

동시에 본 slice 는 **`§ 12.60` (T-1462) 이 명시 이월한 판정의 회수** 다 — components.md **231** 행 각주 말미가 **"대응 `## Contracts` row 는 284 행 1 개로 edge 1 과 1:1 이고 `Prisma client (TCP 5432, libpq protocol)` · `connection pool singleton` 어구가 위 판정의 반증 · 방증 단서이나 판정은 파생 영향 (1) 소관"** 이라고 적어 뒀다. `§ 12.62` 가 `§ 12.55` 의 · `§ 12.63` 이 `§ 12.54` 의 · `§ 12.64` 가 `§ 12.56` 의 이월을 회수한 것과 **동형** 이며, **4 회 연속** 이다. 따라서 **DB connection seam 정의 (= `prisma.service.ts` 단일 파일로 수렴하는 실 wire 지점) 도 `§ 12.60` 승계 + 유효성 재검증** 이며 본 절 신설이 아니다. 본 slice 종료 시 **db 그룹 1/1 마감 · 표 17 중 14 판정 완료 · 잔여 3 (egress)** 이 된다.

planner 사전 확인 — **아래는 전부 가설이며 전제가 아니다** (T-1440 AC 1 이후 planner 기대가 실측에 반증·정정된 선례가 **28** 회 있고, 직전 T-1466 에서도 LLM hit 기대 **8** 이 실측 **12** 로 정정됐다). executor 는 AC 1 에서 전부 재측정하고 **기대와 다르면 그 축의 판정을 실측대로 뒤집는다**. ① **결선 실재** — `§ 12.60` 이 edge 86 을 **참** (`prisma.service.ts` **25** 행 `PrismaPg({ connectionString: process.env.DATABASE_URL … })` · **34** 행 `super({ adapter: … })` · **41** 행 `$connect()`) 으로 닫았으므로 승계 가능성이 크다. ② **message format 셀의 `Prisma client`** — `§ 12.60` 이 실 socket 주체를 `@prisma/adapter-pg` 의 `PrismaPg` → pg Pool 로 확정해 **부분참** 승계 가능성. ③ **`TCP 5432`** — `§ 12.60` 이 `src/**` **0 hit** · 근거가 `docker-compose.yml` **22** 행 · CI service 정의뿐임을 확정해 **배포 층 사실 (부분참)** 승계 가능성. ④ **`libpq protocol` claim** — **본 slice 의 가장 값비싼 새 축** 이다. edge label (`TCP 5432 (Prisma client)`) 에 없던 어구라 ## Out of Scope

- **코드 · schema · 배포 자산 · CI · dependency · agent 정의 변경 절대 금지** — `src/` · `web/` · `test/` · `prisma/` · `scripts/` · `deploy/` · `docker-compose.yml` · `Dockerfile` · `.github/workflows/` · `package.json` · `.claude/agents/` 는 diff 에 등장하면 안 된다 (`grep` 열람은 read-only 라 허용). **축 ④ 가 `libpq protocol` 을 거짓으로 확정해도 `pg-native` · `libpq` 를 도입하지 않는다** (새 dependency = §5 BLOCKED 게이트). **축 ⑤ 가 pool 구성 부재를 확인해도 `connection_limit` 를 추가하지 않는다.**
- **`§ 12.64` 축 ③ 의 `concurrency limit` 잔여 이슈 수리 금지** — 본 slice 는 그것을 **파생 영향 (30) 목록에 doc 축 한정으로 기록만** 한다. `p-limit` 도입 · semaphore 구현 · 282 행 표 셀 수정 어느 것도 하지 않는다.
