# T-0931 — realdata-e2e dual-leg run report body cross-branch single-source convergence non-gated smoke

## Why

PLAN.md 109행 (🟢 실 평가 e2e, P5) step④ (daily-test dual-leg run 결과 rolling-issue 멱등 박제) chain 의 **body medium 이 두 action 분기(create / update) 의 gh argv 로 단일 source 관통하는 seam** 이 아직 어떤 smoke 에도 chain 그물로 묶이지 않았다. step④ 의 rolling-issue 박제는 검색 결과에 따라 두 action 분기로 갈린다:

- **create 분기** — 빈 search(`"[]"`, marker 미매칭) → action `{action:"create"}` → 종단 컴포저가 `["issue","create","--title", createArgs.title, "--body", createArgs.body, ...]` argv 산출. `createArgs.body` = `descriptor.body`(command-args 빌더 line 146).
- **update 분기** — marker-매칭 hit(1+건) → action `{action:"update", issueNumber:N}` → 컴포저가 `["issue","edit",String(N),"--title", updateArgs.title, "--body", updateArgs.body]` argv 산출. `updateArgs.body` = `descriptor.body`(command-args 빌더 line 152).

즉 **어느 action 분기로 가든 이슈 본문(`--body` 원소)은 동일 `descriptor.body` 단일 source 로부터 byte-identical 하게 나와야** step④ 의 rolling-issue 멱등(REQ-009 — "동일 run 의 이슈"가 create/update 어느 경로로도 같은 본문(선두 marker 라인 포함)으로 수렴)이 성립한다: 오늘 밤 run 이 이슈를 새로 만들 때(create)와 내일 밤 run 이 그 이슈를 갱신할 때(update)의 `--body` 가 동일해야 — 특히 body 선두의 marker 라인이 동일해야 — 다음 밤 검색이 그 이슈를 **여전히** marker 로 찾아 중복 생성 대신 재갱신한다. 만약 create body 와 update body 가 어긋나면(silent drift) — 갱신이 자기 본문(및 선두 marker)을 바꿔 멱등 추적이 깨진다.

그러나 이 **body 의 두 action 분기 argv single-source 관통** 은 어느 smoke 도 chain 그물로 검증하지 않는다:

- 형제 T-0930(title cross-branch single-source)은 **title medium** 의 create argv `--title` ↔ update argv `--title` 관통만 자산화한다 — body medium 은 다루지 않는다. 본 task 는 그 title 대칭 **body medium sibling(축=cross-branch)**.
- 형제 T-0928(create-branch marker cross-call)·T-0929(update-branch marker cross-call)는 body **선두 marker 라인** 이 search argv 검색 marker 와 동일 source 로부터 관통함(두 gh 호출 사이 cross-call, medium=marker 단일 라인)만 자산화한다 — create argv 의 **전체 body element** 와 update argv 의 **전체 body element** 가 서로 byte-identical 함(두 action 분기 cross-branch, medium=body 전체)은 미단언. cross-call 축(한 분기 내 두 호출)과 cross-branch 축(두 action 분기)은 다르다.
- 형제 T-0915(descriptor body confluence)는 **descriptor 수준** 에서 descriptor.body 의 구성(선두 marker 라인 + 렌더 markdown)만 자산화한다 — body 가 **하류 create/update argv 의 `--body` 원소로 관통** 함(두 분기 byte-identical)은 미단언. descriptor 문자열 구성 축과 argv 관통 축은 다르다.
- 형제 T-0927(gh-command-plan argv single-source)은 plan.argv 가 single-source gh-argv 빌더 산출과 byte-identical 함(각 분기 내부 argv 정합)만 자산화한다 — create body 와 update body 가 **서로** byte-identical 함(cross-branch body 수렴)은 미단언(분기별 독립 대조라 두 분기 body 를 서로 대조하지 않음).

본 task 는 그 **body cross-branch seam** 을 닫는다 — T-0930(title cross-branch, medium=title)의 **body medium 대칭 sibling(축=cross-branch)**. chain: 두 leg outcome + run → report → descriptor → commandArgs 를 통과시켜 유효 commandArgs 를 얻고, (1) 빈 search(`"[]"`)에 종단 컴포저를 적용해 create-branch plan 을, (2) marker-매칭 hit stdout 에 적용해 update-branch plan 을 각각 산출한 뒤, **create-branch plan.argv 의 `--body` 다음 원소 와 update-branch plan.argv 의 `--body` 다음 원소 가 둘 다 `descriptor.body` 와 byte-identical** 함을 박제한다.

issue-still-relevant 확인(2026-07-12): dual-leg smoke 중 파일명·본문에 `body` + `cross-branch`(create/update 두 argv 전체 body element) single-source 수렴을 결합한 것 = **0개**(`ls test/smoke | grep dual-leg | grep body` = descriptor-body-confluence(T-0915, descriptor 수준) / create-branch-...-createbody(T-0928, 선두 marker cross-call) / update-branch-...-editbody(T-0929, 선두 marker cross-call) 뿐 — 전체 body element 의 두 action 분기 cross-branch 는 0). `descriptor.body`(T-0896)·`createArgs.body`/`updateArgs.body`(T-0897, 둘 다 descriptor.body)·종단 컴포저 create/update 분기 argv(T-0899/T-0902) 배선은 이미 main 에 박제됨 — 본 task 는 그 배선을 **다시 만들지 않고** 두 action 분기에서 body 가 동일 source 로부터 관통함을 대조하는 **smoke 그물만** 신설. `git log origin/main` 동일 영역(dual-leg body cross-branch 수렴 smoke) 박제 commit 0. T-0930 이 title medium 을 닫았으므로 본 task 로 두 argv medium(title / body)의 두 action 분기 관통이 모두 봉합된다.
