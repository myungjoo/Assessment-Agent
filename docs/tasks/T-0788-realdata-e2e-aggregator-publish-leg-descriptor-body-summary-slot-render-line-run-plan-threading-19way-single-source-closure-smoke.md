# T-0788 — realdata-e2e step④ aggregator publish-leg descriptor.body summary-slot→render-line per-slot 1:1 thread 합류 19-way single-source closure non-gated build-time smoke 신설

## Why

PLAN.md §109(🟢 실 평가 e2e, P5)의 build-time 순수 layer 는 최외곽 단일 진입 `buildRealDataE2eRunPlan(seeds, modelId, run)` → `{pipeline, run}`(T-0597)을 산출하고, 그 `runPlan` 을 pre-실행 aggregator `buildRealDataE2eStepArgs(runPlan, activities, results)` → `{evaluation, publish}`(T-0601)에 통째로 넘긴다. 직전 sweep(T-0778~0787)은 aggregator 산출의 세 leg(collect·evaluate·publish) 표면 + 세 leg 내부-shape(collect serviceIdentities 배열 깊이 T-0785, evaluate input 필드 깊이 T-0786, publish summary 집계 깊이 T-0787)를 단일 source 로 묶어 18-way 를 완성했다. 특히 publish-leg 의 descriptor.body 축은 T-0777(aggregator 9-way) 이 `stepArgs.publish.report.descriptor.body == buildRealDataResultIssueCommandPlan(results, runPlan.run).report.descriptor.body` **top-level byte-identical** 로만 합류시켰다.

그러나 publish-leg 의 **descriptor.body render-line 내부-shape 깊이**(RealDataResultSummary → markdown body 라인 차원)에는 18-way 가 닫지 않은 seam 이 남아있다 — aggregator 가 산출한 `stepArgs.publish.report.descriptor.body`(마크다운 문자열)가, 그 leg 의 `report.summary`(type `RealDataResultSummary`)의 각 슬롯값(`count`·`byDifficulty`(3 슬롯)·`byContribution`(4 슬롯)·`totalVolume`)으로부터 **슬롯별 1:1 렌더 불변식**(난이도 분포 표의 `DIFFICULTIES` 순서 3행 각각이 `| <difficulty> | <byDifficulty[d]> |`, 기여도 분포 표의 `CONTRIBUTION_LEVELS` 순서 4행 각각이 `| <level> | <byContribution[c]> |`, `- 평가 단위 수: <count>`·`- 총 volume: <totalVolume>` 라인, 그리고 marker 라인 직후 한 줄 요약 `formatRealDataResultSummaryLine(summary)` 의 `count=N · volume=V · 난이도(easy/medium/hard)=a/b/c · 기여도(zero/low/medium/high)=p/q/r/s` 토큰, 그리고 **전 enum 슬롯 라인 존재**(미등장 분류도 표 행 존재·값 0 라인))으로 production 렌더 위임 `renderRealDataResultSummaryMarkdown(summary)` + `formatRealDataResultSummaryLine(summary)` 와 byte-identical 임은 aggregator+resolve 종단 closure 에 미합류다.

publish-leg descriptor.body render-line 내부-shape 축은 18-way 가 잡은 18축과 distinct 한 표면이다:

- **publish-leg descriptor.body summary-slot→render-line per-slot 1:1 thread 축(본 task 의 새 표면)** — aggregator 가 `buildRealDataE2eStepArgs` 위임 publish step → `buildRealDataResultIssueCommandPlan(results, run)`(T-0594) → `buildRealDataResultReportPlan`(T-0593) → `buildRealDataResultIssueDescriptor(summary, run)`(T-0582) 의 body 합성(marker 라인 + `formatRealDataResultSummaryLine(summary)` + `renderRealDataResultSummaryMarkdown(summary)` 3 블록, `"\n"` join)으로 산출한 `stepArgs.publish.report.descriptor.body` 가:
  - `renderRealDataResultSummaryMarkdown(stepArgs.publish.report.summary)`(production 렌더 위임 직접 호출) 산출 블록과 **byte-identical substring**(body 가 그 markdown 본문을 포함·종단 블록으로 가짐), AND `formatRealDataResultSummaryLine(summary)`(한 줄 요약 위임 직접 호출) 산출이 body 의 한 줄 요약 라인과 byte-identical.
  - **per-slot 1:1 라인 렌더**: 모든 `d ∈ DIFFICULTIES` 에 대해 body 가 `| ${d} | ${summary.byDifficulty[d]} |` 라인을 정확히 포함(`DIFFICULTIES` 순서대로 3행), 모든 `c ∈ CONTRIBUTION_LEVELS` 에 대해 `| ${c} | ${summary.byContribution[c]} |` 라인 포함(`CONTRIBUTION_LEVELS` 순서대로 4행), `- 평가 단위 수: ${summary.count}`·`- 총 volume: ${summary.totalVolume}` 라인 포함(본 task 는 spec-로컬 독립 재유도와의 1:1 + production 렌더 위임 byte-identical 만 단언, 렌더 로직 자체 재구현 0).
  - **전 enum 슬롯 라인 존재 boundary**: 난이도 표는 정확히 3행(`DIFFICULTIES` 전 슬롯, 미등장 slot 도 `| hard | 0 |` 같은 값-0 행 존재), 기여도 표는 정확히 4행(`CONTRIBUTION_LEVELS` 전 슬롯, 미등장도 값-0 행 존재) — body 라인에서 슬롯 누락 0(표현 layer 행 누락 0).
  - **raw-not-stored boundary**(REQ-032/059) — body 가 count·volume·enum 분포 카운트·한 줄 요약 토큰만 보유, `narrative` 본문·raw 활동 본문·unitId 어휘 미surface(EvaluationResult.narrative 가 descriptor.body 로 새지 않음).
  - 이 1:1 이 aggregator 가 resolve 로 thread 하는 **그 동일 `runPlan` 의 publish-leg** 에서 나온다(`report.descriptor.body` 가 `report.summary`·`commandArgs` 와 같은 `buildRealDataResultIssueCommandPlan(results, runPlan.run)` 산물, 18-way 묶음 항).

직전 sibling 들은 이 descriptor.body render-line 내부-shape 축을 aggregator convergence closure 에 합류시키지 않았다:
- **T-0787 (aggregator 18-way)**: publish-leg summary 내부-shape per-result 1:1 집계(count·byDifficulty 3슬롯·byContribution 4슬롯·totalVolume 가 results[] 로부터 원소별 재유도) + 17축을 묶었으나 **그 summary 슬롯값이 descriptor.body 의 markdown 라인으로 어떻게 렌더되는가(슬롯→라인 매핑 깊이)는 미합류**(summary 는 RealDataResultSummary 객체 슬롯까지만, body 문자열 라인까지의 1:1 은 다루지 않음).
- **T-0777 (aggregator 9-way)**: `stepArgs.publish.report.descriptor.body == buildRealDataResultIssueCommandPlan(results, runPlan.run).report.descriptor.body` top-level byte-identical(`toEqual`)만 — body 문자열을 한 덩어리로 deep-equal 비교(SSOT 동일성)에 그치고, **그 body 안의 개별 summary 슬롯값↔라인 per-slot 1:1 매핑·난이도/기여도 표 행별 재유도·전 enum 슬롯 라인 존재(미등장 0)·한 줄 요약 토큰 슬롯별 분해** 단언 0(body 를 불투명 문자열로만 다룸).
- **T-0778~0786 (aggregator 10~17-way)**: descriptor.body render-line 내부 미합류 또는 command-args/search/resolve/collect-leg/evaluation-leg/summary-object 축만 — body 라인 깊이 1:1 합류 0.
- **summary-markdown helper spec / summary-line helper spec / descriptor-body-consistency helper spec**: `renderRealDataResultSummaryMarkdown`(T-0581) + `formatRealDataResultSummaryLine`(T-0642) + `assertRealDataResultIssueDescriptorBodyConsistent`(T-0646) self-guard·spec 가 슬롯→라인 렌더·body 3 블록 구조를 박제했으나 **aggregator(`buildRealDataE2eStepArgs`) chain 진입·resolve·post 미합류**(렌더 helper 단독 spec — aggregator 산출 descriptor.body 의 라인 깊이 ↔ summary 슬롯 종단 정합 0).

본 task 는 그 빈 자리를 채워 **aggregator 가 산출한 publish-leg report.descriptor.body(마크다운)가 그 leg report.summary 로부터 production renderRealDataResultSummaryMarkdown + formatRealDataResultSummaryLine 와 byte-identical·슬롯별 1:1 라인 렌더(전 enum 슬롯 라인 존재/미등장 0, narrative key 부재) 임을, summary 내부-shape per-result 집계·summary top-level 재유도·evaluation-leg·collect-leg·command-args·resolve·post 와 묶어 closure 에 합류**시킨다. 단일 source `(seeds, modelId, run, activities, results, search-stdout, exec-stdout)` 로부터:

1. **publish-leg descriptor.body summary-slot→render-line per-slot 1:1 thread(축 19, 본 task 의 새 표면)** — `stepArgs = buildRealDataE2eStepArgs(runPlan, activities, results)` → `stepArgs.publish.report.descriptor.body` 가 그 leg `stepArgs.publish.report.summary` 로부터 `renderRealDataResultSummaryMarkdown(summary)`(production 렌더 위임 직접 호출) 블록을 종단 substring 으로 포함하고 `formatRealDataResultSummaryLine(summary)` 라인을 포함, body split("\n") 에서 모든 `d ∈ DIFFICULTIES` 의 `| d | byDifficulty[d] |` 행 + 모든 `c ∈ CONTRIBUTION_LEVELS` 의 `| c | byContribution[c] |` 행 + `- 평가 단위 수: count` + `- 총 volume: totalVolume` 라인을 슬롯별 1:1 로 포함, 난이도 표 정확히 3행·기여도 표 정확히 4행(미등장 슬롯도 값-0 행 존재). difficulty 3 슬롯·contribution 4 슬롯 모두 등장·일부 반복하는 multi-slot results 합성.
2. **publish-leg summary 내부-shape per-result 1:1 집계(축 18, 18-way 묶음 항)** — `stepArgs.publish.report.summary` 가 `buildRealDataResultSummary(results)`(production 위임) 와 byte-identical·원소별 1:1(count·byDifficulty 3슬롯·byContribution 4슬롯·totalVolume, 전 enum 슬롯 존재/미등장 0).
3. **publish-leg descriptor + summary top-level 재유도(축 7/9 묶음 항)** — `stepArgs.publish.report.descriptor.body` byte-identical `buildRealDataResultIssueCommandPlan(results, runPlan.run).report.descriptor.body`, `report.summary` byte-identical `...report.summary`(command-plan 경유 — aggregator 와 동일 위임 SSOT).
4. **evaluation-leg input 내부-shape 1:1(축 17 묶음 항)** — `stepArgs.evaluation.inputs[i]` 가 `mapActivityToEvaluationInput(activities[i])` 와 필드별 byte-identical(unitId 합성·contributionKind R-30·metadata reference·raw key 부재).
5. **collect-leg serviceIdentities 내부-shape + collectCallArgs top-level 재유도(축 16 묶음 항)** — `collectCallArgs[i].person.serviceIdentities` 가 `seeds[i]` `{service,externalId}` 추림과 1:1, `collectCallArgs == buildRealDataCollectCallArgs(seeds)`.
