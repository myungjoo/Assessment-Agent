# T-0932 — realdata-e2e dual-leg run report create-branch labels single-source + update-absence orthogonal non-gated smoke

## Why

PLAN.md 109행 (🟢 실 평가 e2e, P5) step④ (daily-test dual-leg run 결과 rolling-issue 멱등 박제) chain 의 **labels medium 이 create 분기 argv 로 단일 source 로부터 전개되고 update 분기 argv 에는 전무한 orthogonality seam** 이 아직 어떤 smoke 에도 chain 그물로 묶이지 않았다. step④ 의 rolling-issue 박제는 검색 결과에 따라 두 action 분기로 갈리는데, labels 는 그중 **create 분기에만** 붙는다:

- **create 분기** — 빈 search(`"[]"`, marker 미매칭) → action `{action:"create"}` → 종단 컴포저가 `["issue","create","--title", createArgs.title, "--body", createArgs.body, "--label", labels[0], "--label", labels[1], ...]` argv 산출. 각 label 은 `commandArgs.createArgs.labels`(고정 결정론 상수 집합의 복제본, command-args 빌더 line 148)의 원소를 순서 보존해 `["--label", <label>]` flag pair 로 전개(gh-argv 빌더 line 124–127).
- **update 분기** — marker-매칭 hit(1+건) → action `{action:"update", issueNumber:N}` → 컴포저가 `["issue","edit",String(N),"--title", updateArgs.title, "--body", updateArgs.body]` argv 산출. **`--label` 토큰도, 어떤 label 원소도 없다**(gh-argv 빌더 line 141–149 — edit argv 는 labels 를 전개하지 않음).

즉 **labels 는 create-only medium** 이다: 오늘 밤 run 이 이슈를 새로 만들 때(create)만 label 을 붙이고, 내일 밤 run 이 그 이슈를 갱신할 때(update)는 label 을 재부여하지 않는다(이미 붙어있는 label 을 건드리지 않음 — 멱등 갱신). 만약 update 분기 argv 에 `--label` 이 새면(silent leak) — 갱신 때마다 label 을 중복/재부여해 이슈 메타가 불안정해지거나 gh edit 이 실패한다. 또 create 분기 label 전개가 단일 source(고정 labels 상수)에서 순서 보존·pair 형태로 나오지 않으면 — 라벨 누락/뒤섞임/오염된 flag 로 이슈가 잘못 분류된다.

그러나 이 **labels 의 create-branch single-source 전개 정합 + update-branch 부재 직교** 는 어느 smoke 도 chain 그물로 검증하지 않는다:

- 형제 T-0930(title cross-branch)·T-0931(body cross-branch)은 **title / body medium** 이 create argv ↔ update argv 로 **두 분기 모두 등장**하며 byte-identical 관통함(cross-branch 대칭)만 자산화한다 — labels 는 다루지 않는다. 게다가 labels 는 title/body 와 달리 **create 에만 등장하는 비대칭 medium** 이라 축이 cross-branch 대칭이 아니라 create single-source + update absence orthogonality 다.
- 형제 T-0927(gh-command-plan argv single-source)은 plan.argv 가 single-source gh-argv 빌더 산출과 byte-identical 함(각 분기 내부 argv 정합)만 자산화한다 — labels 가 **정확히 `["--label", <label>]` pair 형태로 순서 보존 전개**되는 세부, create 분기에만 labels 가 붙고 update 분기에는 전무하다는 **비대칭(orthogonality)** 은 미단언(분기별 내부 정합이라 labels 유무의 두 분기 대조를 하지 않음).
- 형제 T-0921(marker⊥issueNumber orthogonal)은 **searchArgv marker medium 과 editArgv issueNumber medium** 이 서로 직교(독립 source)함만 자산화한다 — labels medium 의 create-only 직교(update 부재)는 다른 축이다.
- 형제 T-0928/T-0929(marker cross-call)·T-0915(descriptor body confluence)·T-0919(search-argv marker 4-boundary)·T-0920(edit-argv issueNumber)는 모두 marker / body / issueNumber medium 이며 labels 를 다루지 않는다.

본 task 는 그 **labels create-single-source + update-absence orthogonal seam** 을 닫는다 — T-0930/T-0931(title·body cross-branch)의 **labels medium sibling(단 축=create single-source + update absence orthogonality, cross-branch 대칭 아님)**. chain: 두 leg outcome + run → report → descriptor → commandArgs 를 통과시켜 유효 commandArgs 를 얻고, (1) 빈 search(`"[]"`)에 종단 컴포저를 적용해 create-branch plan 을, (2) marker-매칭 hit stdout 에 적용해 update-branch plan 을 각각 산출한 뒤, **create-branch plan.argv 의 `--label` flag-pair 원소들이 `commandArgs.createArgs.labels` 로부터 순서 보존·pair 형태로 byte-identical 전개** 되고 **update-branch plan.argv 에는 `--label` 토큰 및 어떤 label 원소도 부재(orthogonality)** 함을 박제한다.

issue-still-relevant 확인(2026-07-12): dual-leg smoke 중 파일명·본문에 `label` medium(create-branch labels 전개 + update 부재 orthogonality) single-source 를 결합한 것 = **0개**(`ls test/smoke | grep dual-leg | grep -iE "label"` = 결과 없음 — title-cross-branch(T-0930) / body-cross-branch(T-0931) / marker cross-call(T-0928/29) / descriptor-body(T-0915) / marker⊥issueNumber(T-0921) 뿐, labels medium 은 0). `commandArgs.createArgs.labels`(고정 상수 복제, command-args 빌더 T-0897) 및 create 분기 `--label` pair 전개·update 분기 labels 부재(gh-argv 빌더 T-0898/종단 컴포저 T-0899) 배선은 이미 main 에 박제됨 — 본 task 는 그 배선을 **다시 만들지 않고** create 분기 labels 전개 정합 + update 분기 부재를 대조하는 **smoke 그물만** 신설. `git log origin/main` 동일 영역(dual-leg labels create-single-source + update-absence smoke) 박제 commit 0. T-0930/T-0931 이 title·body medium 을 닫았으므로 본 task 로 세 argv medium(title / body / labels)의 두 action 분기 관통·부재 정합이 모두 봉합된다.
