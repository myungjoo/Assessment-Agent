# T-1086 — daily-step-dual-leg-run-report-issue-descriptor-body 구조-검사 선행성 order-lock (clean leg — 신규 namespace import + spyOn 인프라)

## Why

P5 test-hardening 의 realdata-e2e 구조-guard 선행성 sweep(T-1065 §D 후보 (a))은 leg 1 result-report-plan(T-1066) → … → leg 19 result-outcome-step-args(T-1084) → leg 20 result-issue-descriptor-body(T-1085)로 이어졌다. T-1085 Follow-up 이 leg 21 후보로 **우선 지목**한 동형 dual-leg mirror **daily-step-dual-leg-run-report-issue-descriptor-body consistency 가드**(`test/helpers/realdata-e2e-daily-step-dual-leg-run-report-issue-descriptor-body-consistency.ts`)를 leg 21 로 삼는다. 이 가드 `assertRealDataDailyStepDualLegRunReportIssueDescriptorBodyConsistent`(L138~)는 실 평가 e2e daily-step dual-leg run report 이슈 박제 descriptor 의 `body` 2 블록 구조(marker 라인 → 빈 줄 → 마크다운 본문)를 single source `report` 로 위임 재유도(`renderRealDataDailyStepDualLegRunReportMarkdown(report)` L157)해 byte-identical 대조하는 post-composition 무결성 가드다(README.md 109행 step ④ 결과 박제 chain 의 body 합성 무결성 / REQ-032·REQ-059). 요약축 result-issue-descriptor-body(T-1085, T-0646)의 daily-step mirror — 요약축 body **3 블록**(marker → 빈 줄 → 한 줄 요약 → 빈 줄 → markdown)을 daily 축 body **2 블록**(marker → 빈 줄 → markdown)으로 축소 적용한다. 재유도 delegate 는 **1개**(`renderRealDataDailyStepDualLegRunReportMarkdown`), 재유도보다 앞서는 error 범주는 **2종**(descriptor 구조 TypeError + 비식별 식별자 Error).

**clean-leg 성격(variant 아님)**: T-1084 leg 는 spec 이 delegate 를 이미 namespace import + happy-path spyOn 하고 있어 기존 인프라 재사용 variant 였다. 반면 본 leg 의 spec(총 519줄)은 delegate `renderRealDataDailyStepDualLegRunReportMarkdown` 를 **value import 조차 하지 않고**(spec 은 가드 함수만 import — L32) `import * as` namespace import 도 `jest.spyOn` 도 `toHaveBeenCalled*` 도 전무하다(pre-check grep: `toHaveBeenCalledTimes` = 0, `jest.spyOn` = 0, `import * as` = 0). 따라서 본 leg 는 T-1082/T-1083/T-1085 와 같은 **clean-leg** — delegate 의 **신규 namespace import 신설 + spyOn 인프라 신설**이 필요하다.

planner pre-check(실 grep + read, 2026-07-18, HEAD b0d702e2 = T-1085 머지 포함)로 확인한 gap: 이 가드는 본문에서 **상위 구조 assert**(`assertDescriptorStructure(descriptor, label)` L146 — descriptor null/undefined·비-object·marker 비-string·body 비-string → TypeError)와 **비식별 식별자 guard**(`assertNonBlank(report.gitSha, "gitSha")` L151 / `assertNonBlank(report.dateToken, "dateToken")` L152 — 빈/공백-only → producer 동형 plain Error) **둘 다를** body 마크다운 재유도 위임(`renderRealDataDailyStepDualLegRunReportMarkdown(report)` L157)보다 **먼저** 수행한다(구조검사 L146 + 비식별 검사 L151~152 < 재유도 L157). 구조·비식별 검사와 재유도 **사이에 RangeError 분기가 없다** — 값 정합 위반 RangeError(불변식 1~4, L163~L188 이후)는 전부 재유도 **뒤**에 온다. 그러나 대응 spec 의 두 error-path describe(`error path — report 식별자 빈-공백 → producer 동형 Error` L163~, gitSha 빈/공백·dateToken 빈/공백 4건 / `flow/branch — 구조 결손 → TypeError` L206~, descriptor null·비-object·marker 비-string·body null·body 비-string 5건)은 `.toThrow(...)` 만 assert 하고 delegate 호출 횟수를 못박지 않는다. 즉 **재유도-앞 error 입력(구조 결손 또는 비식별 식별자)을 주면 body 마크다운 재유도 delegate 가 `toHaveBeenCalledTimes(0)` 이어야 한다는 선행성**이 spy 로 못박혀 있지 않다. 이를 재유도-앞 9 분기(descriptor null·비-object·marker 비-string·body null·body 비-string / gitSha 빈·공백·dateToken 빈·공백)에 delegate `renderRealDataDailyStepDualLegRunReportMarkdown` `toHaveBeenCalledTimes(0)` 으로 못박아 "구조·비식별 검사 → body 재유도" 순서를 silent 재정렬로부터 방어한다(T-1066~T-1085 와 동형 defense-in-depth, delegate 1개, error 범주 2종). test-only 1파일, production `src`·helper `.ts` 로직 무변경.

**0-call 범위 경계(중요, 두 error 범주)**: 본 leg 의 0-call 선행성은 **재유도(L157)보다 앞서는 두 error 범주**에 적용한다 — (i) descriptor 구조 결손 5 분기(TypeError: descriptor null/undefined·비-object·marker 비-string·body 비-string), (ii) 비식별 식별자 4 분기(producer 동형 Error: gitSha 빈/공백-only·dateToken 빈/공백-only). 두 범주 모두 delegate 호출 **이전**에 throw 하므로 delegate `toHaveBeenCalledTimes(0)`. 값 정합 위반 RangeError(불변식 1~4: 최소 3 라인 미달·마크다운 블록 drift·구분 빈 줄 제거·marker 라인 위치 이동)는 재유도 **후** 발생하므로 delegate 1-call — 이는 값-boundary 대조에 사용한다(0-call 범위 밖).
