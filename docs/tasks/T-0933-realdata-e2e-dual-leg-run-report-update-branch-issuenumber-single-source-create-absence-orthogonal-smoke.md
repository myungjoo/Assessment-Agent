# T-0933 — realdata-e2e dual-leg run report update-branch issueNumber single-source + create-absence orthogonal non-gated smoke

## Why

PLAN.md 109행 (🟢 실 평가 e2e, P5) step④ (daily-test dual-leg run 결과 rolling-issue 멱등 박제) chain 의 **issueNumber medium 이 update 분기 argv 로 단일 source 로부터 관통하고 create 분기 argv 에는 전무한 orthogonality seam** 이 아직 어떤 smoke 에도 chain 그물로 묶이지 않았다. step④ 의 rolling-issue 박제는 검색 결과에 따라 두 action 분기로 갈리는데, issueNumber 는 그중 **update 분기에만** 붙는다:

- **update 분기** — marker-매칭 hit(1+건) → action `{action:"update", issueNumber:N}`(N = marker-매칭 hit 중 최소 number, action resolver) → 종단 컴포저가 `["issue","edit", String(N), "--title", updateArgs.title, "--body", updateArgs.body]` argv 산출. issueNumber 는 `String(action.issueNumber)`(gh-argv 빌더 line 141–149)로 argv **index 2** 에 문자열화되어 온다.
- **create 분기** — 빈 search(`"[]"`, marker 미매칭) → action `{action:"create"}` → 컴포저가 `["issue","create","--title", createArgs.title, "--body", createArgs.body, ...labels]` argv 산출. **어떤 issue-number 원소도, action.issueNumber 필드도 없다**(create action shape 에 issueNumber 필드 자체가 부재, create argv 는 issue-number 토큰을 전개하지 않음).

즉 **issueNumber 는 update-only medium** 이다: 오늘 밤 run 이 이슈를 새로 만들 때(create)는 아직 이슈 번호가 없어 참조하지 않고, 내일 밤 run 이 그 이슈를 갱신할 때(update)만 검색으로 찾은 기존 이슈의 번호 N 을 `gh issue edit N` 의 대상으로 지목한다. 이것은 형제 T-0932 의 labels(create-only medium — create 에만 붙고 update 에는 없음)의 **정확한 거울상**이다: labels 는 create-only, issueNumber 는 update-only. 두 비대칭 medium 이 서로 반대 분기에만 등장하며 상대 분기에는 전무하다.

만약 create 분기 argv 에 issue-number 가 새면(silent leak) — 아직 존재하지 않는 이슈 번호로 `gh issue create` 를 호출해 명령이 실패하거나 엉뚱한 이슈를 건드린다. 반대로 update 분기 argv 의 issueNumber 가 search-hit N 이 아닌 다른 값으로 어긋나면 — 갱신이 엉뚱한 이슈를 덮어써 멱등 rolling-issue 추적이 깨진다(REQ-009 — 동일 run 의 이슈를 다음 밤 검색이 marker 로 찾아 **그 번호로** 재갱신).

그러나 이 **issueNumber 의 update-branch single-source 관통 + create-branch 부재 직교** 는 어느 smoke 도 chain 그물로 검증하지 않는다:

- 형제 T-0932(labels create-only + update-absence)은 **labels medium** 이 create argv 로만 `--label` pair 전개되고 update argv 에는 전무한 orthogonality 만 자산화한다 — issueNumber 는 다루지 않는다. 본 task 는 그 **정확한 거울상**(medium=issueNumber, 축=update-only single-source + create-absence orthogonality)이다.
- 형제 T-0920(edit-argv issueNumber execute-side single-source closure)은 **update 분기 내부**에서 search-hit N → resolveAction → edit-argv → output-parse 가 single-source 로 닫힘만 자산화한다 — issueNumber 가 **create 분기 argv 및 create action 에 전무**하다는 두 분기 비대칭(orthogonality)은 미단언(update 분기 내부 closure 라 create 분기와 대조하지 않음).
- 형제 T-0921(marker⊥issueNumber orthogonal)은 **searchArgv marker medium 과 editArgv issueNumber medium** 이 서로 직교(독립 source, cross-contamination 0)함만 자산화한다 — 이는 **두 다른 medium** 의 직교이며, issueNumber 라는 **한 medium** 의 create/update 분기 비대칭(update-only)은 다른 축이다.
- 형제 T-0930(title cross-branch)·T-0931(body cross-branch)은 title/body 가 **두 분기 모두 등장**하며 byte-identical 관통함(cross-branch 대칭)만 자산화한다 — issueNumber 는 update 에만 등장하는 비대칭 medium 이라 축이 다르다.
- 형제 T-0927(gh-command-plan argv single-source)은 plan.argv 가 single-source gh-argv 빌더 산출과 byte-identical(각 분기 내부 정합)만 자산화한다 — issueNumber 가 정확히 index 2 로 관통하는 세부, create 분기에는 issue-number 가 전무하다는 **비대칭(orthogonality)** 은 미단언.

본 task 는 그 **issueNumber update-branch single-source + create-absence orthogonal seam** 을 닫는다 — T-0932(labels create-only + update-absence)의 **거울상 sibling(medium=issueNumber, update-only ⊥ create)**. chain: 두 leg outcome + run → report → descriptor → commandArgs 를 통과시켜 유효 commandArgs 를 얻고, (1) marker-매칭 hit stdout 에 종단 컴포저를 적용해 update-branch plan 을, (2) 빈 search(`"[]"`)에 적용해 create-branch plan 을 각각 산출한 뒤, **update-branch plan.argv[2] === String(N) === String(action.issueNumber)** 로 search-hit number 로부터 단일 source 관통 되고 **create-branch plan.argv 및 action 에는 issueNumber 원소·필드가 부재(orthogonality)** 함을 박제한다.

issue-still-relevant 확인(2026-07-12): dual-leg smoke 중 파일명·본문에 issueNumber medium 의 **create-absence / update-only** 비대칭(create 분기 부재 orthogonality)을 결합한 것 = **0개**(`ls test/smoke | grep dual-leg | grep -iE "create-absence|update-only"` = 결과 없음 — issueNumber 는 T-0920 execute-side closure(update 내부) / T-0921 marker⊥issueNumber(두 medium 직교) 뿐, create-branch 부재 orthogonality 는 0). `action.issueNumber`(marker-매칭 hit 최소 number, action resolver T-0898) 및 update 분기 `String(issueNumber)` index 2 전개·create 분기 issueNumber 부재(gh-argv 빌더 T-0899/종단 컴포저 T-0902) 배선은 이미 main 에 박제됨 — 본 task 는 그 배선을 **다시 만들지 않고** update 분기 issueNumber 관통 정합 + create 분기 부재를 대조하는 **smoke 그물만** 신설. `git log origin/main` 동일 영역(dual-leg issueNumber update-only + create-absence smoke) 박제 commit 0. T-0932 가 labels create-only medium 을 닫았으므로 본 task 로 두 비대칭 medium(labels: create-only, issueNumber: update-only)의 orthogonality 쌍이 모두 봉합된다.
