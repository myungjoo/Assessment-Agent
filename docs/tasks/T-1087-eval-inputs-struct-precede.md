# T-1087 — evaluation-inputs 구조-검사 선행성 order-lock (clean leg — 신규 namespace import + spyOn 인프라)

## Why

P5 test-hardening 의 realdata-e2e 구조-guard 선행성 sweep(T-1065 §D 후보 (a))은 descriptor-body 축(result-issue T-1085 → daily-step T-1086)과 step-args 축(evaluation T-1082 / result-publish T-1083 / result-outcome T-1084)을 소진했다. T-1086 Follow-up 이 leg 22 후보로 지목한 **producer/aggregator layer 잔여 축**을 재감사한 결과, `evaluation-inputs consistency 가드`(`test/helpers/realdata-e2e-evaluation-inputs-consistency.ts`)가 **imported value delegate 를 요소별로 재유도 호출**하면서 재유도-앞 구조 error-path 에 delegate 0-call spy 가 결손된 적격 축으로 확인됐다. 이 가드 `assertRealDataEvaluationInputsConsistentWithSources`(L150~)는 실 평가 e2e 체인 step ②(evaluation) 에서 `activities` 를 `mapActivityToEvaluationInput` 로 변환해 산출한 `EvaluationInput[]` 가, 동일 source `activities` 를 single-source producer(`mapActivityToEvaluationInput`, `src/assessment-evaluation/domain/evaluation-input.mapper`)로 요소별 재유도(`activities.map((a) => mapActivityToEvaluationInput(a))` L163~164)한 expected 와 배열 차원(길이 + 각 원소 내용)에서 정합함을 대조하는 post-mapping 무결성 가드다(README.md 109행 step ② 활동→평가입력 변환 chain / REQ-030·REQ-059). 재유도 delegate 는 **1개**(`mapActivityToEvaluationInput`), 재유도보다 앞서는 error 범주는 **1종**(배열-구조 TypeError 2 guard × 총 5 분기).

**clean-leg 성격(variant 아님)**: 본 leg 의 spec(총 267줄)은 delegate `mapActivityToEvaluationInput` 를 **named value import(L18)** 로 가져오되 오직 **fixture 합성 helper**(정합 evaluationInputs 를 join 산출 — L73 `return activities.map((a) => mapActivityToEvaluationInput(a))`, L196 length-김 fixture) 에만 쓰고, `import * as` namespace import 도 `jest.spyOn` 도 `toHaveBeenCalled*` 도 전무하다(pre-check grep: `toHaveBeenCalledTimes` = 0, `jest.spyOn` = 0, `import * as` = 0). 따라서 본 leg 는 T-1082/T-1083/T-1085/T-1086 와 같은 **clean-leg** — delegate 의 **신규 namespace import 신설 + spyOn 인프라 신설**이 필요하다(named value import 은 spy target 이 될 수 없으므로 별도 namespace import 추가).

planner pre-check(실 grep + read, 2026-07-18, HEAD fc6d6b53 = T-1086 머지 포함)로 확인한 gap: 이 가드는 본문에서 **상위 배열-구조 assert 2개**(`assertEvaluationInputsStructure(evaluationInputs)` L156 — evaluationInputs 가 `!Array.isArray` → TypeError / `assertActivitiesStructure(activities)` L157 — activities 가 `!Array.isArray` → TypeError) **둘 다를** 요소별 재유도 위임(`activities.map((a) => mapActivityToEvaluationInput(a))` L163~164)보다 **먼저** 수행한다(구조검사 L156~157 < 재유도 L163). 구조 검사와 재유도 **사이에 RangeError 분기가 없다** — 값 정합 위반 RangeError(길이 불일치 L170 / 원소-내용 drift L177~)는 전부 재유도 **뒤**에 온다. 그러나 대응 spec 의 구조 error-path describe(`error path — 구조 결손(TypeError)` L106~: evaluationInputs null L107·undefined L117·비-배열-object L126 / activities null L135·비-배열-string L145)는 `.toThrow(...)` 만 assert 하고 delegate 호출 횟수를 못박지 않는다. 즉 **재유도-앞 error 입력(배열-구조 결손)을 주면 mapper delegate 가 `toHaveBeenCalledTimes(0)` 이어야 한다는 선행성**이 spy 로 못박혀 있지 않다. 이를 재유도-앞 5 분기에 delegate `mapActivityToEvaluationInput` `toHaveBeenCalledTimes(0)` 으로 못박아 "배열-구조 검사 → 요소별 재유도" 순서를 silent 재정렬로부터 방어한다(T-1066~T-1086 와 동형 defense-in-depth, delegate 1개, error 범주 1종). test-only 1파일, production `src`·helper `.ts` 로직 무변경.

**0-call 범위 경계(중요, per-element map 특이점)**: 본 leg 의 0-call 선행성은 **재유도(L163)보다 앞서는 배열-구조 error 범주**에만 적용한다 — evaluationInputs null/undefined/비-배열, activities null/비-배열 (5 분기 모두 delegate 호출 **이전**에 throw → delegate `toHaveBeenCalledTimes(0)`). **재유도 delegate 는 per-element map 호출**이므로 정상 도달·값 drift 경로에서 호출 횟수는 **`activities.length`(1 아님)**임에 유의한다 — happy-path spy 는 `toHaveBeenCalledTimes(activities.length)`, 값 정합 위반 RangeError(길이/원소 drift, 재유도 뒤) 경로도 delegate 가 source `activities` 전량에 대해 호출되므로 `toHaveBeenCalledTimes(activities.length)`(> 0). 이 N-call 특이점이 이전 legs(단일 report 인자 1-call)와의 차이점이며, 0-call 경계는 오직 구조-fail(map 시작 전 throw) 시에만 성립한다. **out-of-scope**: 개별 activity 원소 malformation 으로 `mapActivityToEvaluationInput` 가 map **도중** throw 하는 경우는 delegate 호출을 **수반**하므로(call-then-throw) 0-call 범위 밖(별도 delegate-throw 전파 domain).
