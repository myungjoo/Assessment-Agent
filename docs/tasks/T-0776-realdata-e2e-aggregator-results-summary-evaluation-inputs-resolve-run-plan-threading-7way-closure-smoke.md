# T-0776 — realdata-e2e step④ aggregator results-summary 합류 7-way single-source closure non-gated build-time smoke 신설

## Why

PLAN.md §109(🟢 실 평가 e2e, P5)의 step④ 멱등 search-or-update 의 build-time 순수 layer 는 **검증된 단일 run plan(`buildRealDataE2eRunPlan(seeds, modelId, run)` → `{pipeline, run}`, T-0597)을 pre-실행 aggregator(`buildRealDataE2eStepArgs(runPlan, activities, results)` → `{evaluation, publish}`, T-0601)에 통째로 넘긴다**. 이 aggregator 는 **세 개의 입력 source** 를 받는다 — `runPlan`(검증된 modelId+run), `activities: Activity[]`(수집 산출), `results: EvaluationResult[]`(평가 산출). 직전 sweep(T-0770~T-0775)은 `runPlan` 과 `activities` 두 source 를 closure 에 묶었으나, **세 번째 source `results` 는 closure 에 미합류** 상태다.

`results` source 는 aggregator 의 publish leg 의 `report.summary` 로 흐른다:

- **summary 축(본 task 의 새 표면)** — `stepArgs.publish.report.summary: RealDataResultSummary`(count + difficulty/contribution 분포 + totalVolume, T-0580 집계)는 **동일 `results` source 로부터 재유도**된다. 즉 `stepArgs.publish.report.summary` 가 동일 `results`·동일 `runPlan.run` 으로 직접 호출한 `buildRealDataResultIssueCommandPlan(results, runPlan.run).report.summary` 와 **byte-identical** 이다. 평가 결과 정량 집계(이슈 본문 source)가 단일 검증 `results` source 로부터 재유도됨.

직전 sibling 들은 이 summary 축(=results source)을 closure 에 합류시키지 않았다:
- **T-0775 (aggregator 6-way)**: evaluation leg 의 inputs(activities 재유도)+callArgs.input 페어링+modelId 축 + publish leg 의 marker/searchArgv/run-identity 축을 단일 (runPlan, activities) single-source 로 수렴 박제. 그러나 **publish leg 의 `report.summary`(=results source)는 closure 에 미합류** — `results` 가 evaluation `report.descriptor.marker` body 렌더 source 로만 간접 흐를 뿐, `report.summary` 의 단일-source `results` 재유도 정합은 closure 에 묶이지 않았다.
- **T-0762 (publish-plan↔report-plan convergence)**: publish plan 의 report 가 report-plan 재유도와 정합함을 박제했으나 **aggregator·resolve·post 미합류**(직접 호출 byte-identical 만, aggregator 진입·종단 chain 0).

본 task 는 그 빈 자리를 채워 **세 번째이자 마지막 미합류 입력 source `results` 를 단일-source closure 에 묶어**, 검증 source `(runPlan, activities, results)` 세 source 가 aggregator 의 evaluation leg(inputs=activities 재유도 + modelId=runPlan.pipeline) + publish leg(summary=results 재유도 + marker/searchArgv/run-identity)의 source 임을 resolve+post 까지 묶은 한 chain 으로 박제한다. 단일 source `(runPlan, activities, results, search-stdout, exec-stdout)` 로부터:

1. **publish-leg results-summary 재유도(축 7, 본 task 의 새 표면)** — `stepArgs = buildRealDataE2eStepArgs(runPlan, activities, results)` → `stepArgs.publish.report.summary` 가 동일 `results`·동일 `runPlan.run` 으로 직접 호출한 `buildRealDataResultIssueCommandPlan(results, runPlan.run).report.summary` 와 **byte-identical deep-equal**. 단일 `results` source 의 정량 집계(count·분포·totalVolume)가 aggregator publish report 로 동형 재유도.
2. **evaluation-leg inputs 재유도 + 페어링(축 6, T-0775 cover 영역의 7-way 묶음 항)** — `stepArgs.evaluation.inputs` 가 `buildRealDataEvaluationInputs(activities)` 와 byte-identical, `callArgs[i].input === inputs[i]`.
3. **evaluation-leg modelId thread(축 5)** — 모든 `callArgs[i].options.modelId === runPlan.pipeline.modelId`.
4. **publish-leg 내부 marker 3-축 일치(축 2~4)** — `descriptor.marker === commandArgs.searchQuery === extractSearchMarker(searchArgv)`.
5. **resolve issueNumber + post run-identity(축 1, 종단)** — `resolvePlan = resolveRealDataResultIssueGhCommandPlan(searchStdout, stepArgs.publish.commandArgs)` → `action.update.issueNumber = N` → `outcomeReport = buildRealDataResultOutcomeStepArgs(runPlan, execStdout)` → `{issueNumber, gitSha, dateToken, ...}` 가 동일 runPlan.run 전파.

이 7-way(summary 재유도 + inputs 재유도 + modelId + marker 3-축 + resolve issueNumber + post run-identity)가 **세 검증 source `(runPlan, activities, results)`** single-source 로 수렴함이 **search-or-update 멱등성**(REQ-009)·**raw 미보유 평가 입력/결과 집계 정합**(REQ-032)·**결과 리포트 재실행 정합**(REQ-037)의 aggregator-level "평가 입력 식별(inputs)+평가 정책(modelId)+평가 결과 집계(summary)+publish 식별(marker/searchArgv/run-identity)이 같은 세 검증 source 에서 나옴" 의 종단 닫음이다. **aggregator 의 세 입력 source 가 모두 closure 에 묶이는 마지막 slice** 다.

gap 확인(git grep, origin/main 418f8e5e): `for f in test/smoke/realdata-e2e*.smoke-spec.ts; do (buildRealDataE2eStepArgs AND report.summary AND buildRealDataResultIssueCommandPlan AND resolveRealDataResultIssueGhCommandPlan 4 동시 실 호출) 여부; done` — **0 파일**(직전 fire 실측 확인 — T-0775 는 report.summary 재유도 미합류, T-0762 는 aggregator·resolve·post 미합류). `git log origin/main` 동일 영역 박제 commit 0.

live leg(실 prisma·실 collectForPerson·실 github.com fetch·실 LLM scoring·실 gh CLI 실행·DB·LAN gate) 복제 0·non-gated 항상 실행 — 순수 build-time in-memory 검증만.
